# DocSage: An Information Structuring Agent for Multi-Doc Multi-Entity Question Answering

## 摘要

> 本文提出了一种名为DocSage的端到端智能体框架，用于解决多文档多实体问答（MDMEQA）任务中的核心挑战。该框架通过动态模式发现、结构化信息提取和模式感知关系推理三个核心模块，有效克服了现有LLM和RAG方法在跨文档逻辑追踪和证据链构建上的不足。在两项MDMEQA基准测试中，DocSage显著优于现有最优的长上下文LLM和RAG系统，准确率提升超过27%。

## 详细分析

> **社区热度**: ⭐ 1 (来自 papers.cool)

## 问题定义

该论文旨在解决**多文档多实体问答**（Multi-document Multi-entity Question Answering, **MDMEQA**）任务中的核心挑战，即如何在信息分散于多个非结构化文档的情况下，有效追踪跨文档的实体间隐式逻辑关系并构建可靠的证据链。

具体而言，该研究针对现有方法的关键局限性展开：

1. **标准RAG框架的粗粒度检索缺陷**  
   基于向量相似性的检索机制倾向于选择语义重叠度高的文本片段，而非与实体相关性强的关键事实，导致跨文档推理所需的重要信息被遗漏。

2. **图增强RAG的计算与整合瓶颈**  
   虽然知识图谱能建模实体关系，但在面对大规模、跨文档的碎片化关系网络时，图构建的计算成本高昂，且难以高效整合复杂的异构关系。

3. **大语言模型的注意力扩散与上下文限制**  
   长上下文LLM在处理分散于大量文本中的多实体关系时，存在"上下文稀释"（contextual dilution）现象，即关键实体因注意力饱和而被忽略，难以维持跨文本段的实体关系追踪。

4. **缺乏模式感知（Schema Awareness）**  
   现有方法未能动态构建面向查询的结构化表示，无法系统性地组织分散的实体与关系，导致证据链断裂和实体关系推理不准确。

为应对这些挑战，该论文提出**DocSage**框架，通过**动态模式发现**、**结构化信息抽取**与**模式感知的关系推理**三个核心模块，将非结构化文本转化为查询特定的关系型知识表示，从而实现精确的跨文档实体对齐、多跳推理与可验证的答案生成。

## 相关工作

该论文的相关研究主要集中在两个方向：**基于大语言模型的检索机制**与**结构化增强生成方法**。

### 1. 检索机制与大语言模型结合

- **早期RAG框架**  
  Lewis et al. (2020) 开创了将稠密段落检索与生成模型结合的先河，但在多实体场景中效果有限，因答案需综合多个文档的碎片化信息。

- **检索精度优化**  
  REALM (Arora et al., 2023) 与 FiD (Izacard and Grave, 2021) 通过交叉注意力机制提升检索精度，但本质上将文档视为孤立单元，未能建模跨文档实体间的关键关系。

- **长上下文大语言模型**  
  Claude 3 (Anthropic, 2024)、GPT-4 Turbo (Achiam et al., 2023) 等模型扩展了上下文窗口，但实证研究 (Liu et al., 2025; Lin, 2025a) 揭示其存在"上下文稀释"（contextual dilution）现象，即关键实体因注意力饱和而在长文本中被忽略。

- **混合迭代策略**  
  包括迭代检索与自校正 (Yoran et al., 2024) 以及分层摘要链 (Wang et al., 2023)，但这些方法仍局限于对非结构化文本的线性处理，掩盖了实体间的潜在关系。

### 2. 结构化增强生成

- **表格预训练方法**  
  TableLLM (Zhang et al., 2025a) 通过在表格数据上预训练以提升模式理解能力，但依赖预定义模式，限制了在新领域的适应性。

- **图结构方法**  
  GraphRAG (Edge et al., 2024) 从检索片段中提取（头实体、关系、尾实体）三元组构建知识图谱，以支持关系感知推理，但在文档数量增加时图构建计算开销巨大，且难以高效整合跨文档的复杂碎片化关系网络。

- **动态结构感知框架**  
  StructRAG (Li et al., 2024) 动态识别适合特定任务的结构表示并重构文本内容，但将结构创建作为检索后步骤，与初始信息收集过程解耦；类似地，Structed RAG (Lin, 2025b) 也面临动态提取实体时的计算开销问题。

- **静态知识库方法**  
  包括知识图谱嵌入技术（如 TransE, Bordes et al., 2013）与基于模板的表格生成，这类方法优先处理静态知识库，难以适应维基百科等不断演变的开放域语料。

上述方法的核心局限在于：**要么缺乏模式感知无法系统组织分散实体，要么将结构构建作为后置步骤与检索解耦，或依赖预定义模式缺乏领域适应性**。DocSage 通过动态模式发现与端到端信息结构化流程，针对性地解决了这些缺陷。

## 解决方案

该论文提出 **DocSage** 框架，通过端到端的智能体工作流（agentic pipeline）将非结构化文档集合转化为查询特定的结构化关系表示，从而系统性地解决 MDMEQA 挑战。该框架由三个顺序集成的核心模块构成：

### 1. 交互式模式发现模块（Interactive Schema Discovery）

该模块动态推断回答查询所需的最小可连接关系模式 $S_q$，无需依赖预定义模式。其核心为 **ASK 算法**（Active Schema Discovery via Knowledge-seeking Queries），将模式发现重构为与文档集的交互式对话过程：

- **初始假设生成**：基于查询 $q$ 与文档子集 $D_{sample}$，通过模式推导模型 $M_{schema}$ 生成初始模式假设：
  $$S_q^0 = F_{init}(q, D_{sample})$$

- **不确定性识别与问题生成**：将 $S_q^0$ 应用于更多文档，识别三类不确定性信号：（1）实体对齐冲突；（2）属性值分布异常；（3）缺失关系。针对每类不确定性，生成澄清问题集：
  $$P = \{p_j\} = F_{ask}(S_q^k, D, \text{Uncertainty Signals})$$

- **迭代更新**：以问题集 $P$ 作为新查询检索证据，通过更新函数修正模式：
  $$S_q^{k+1} = F_{update}(S_q^k, A(P, D))$$
  其中 $A$ 表示问题 $P$ 的答案检索过程。算法在模式稳定或所有查询得到充分回答时收敛。

### 2. 逻辑感知结构化抽取模块（Logic-Aware Structured Extraction）

该模块将非结构化文本转换为符合 $S_q$ 的语义连贯关系表，并通过 **CLEAR 机制**（Cross-record Logic Enforcement for Accuracy Reinforcement）提供错误保证：

- **基础元组抽取**：使用抽取模型 $M_{ext}$ 与模式 $S_q$ 从文档块 $d_k$ 生成候选元组 $t_k$。

- **双层校正机制**：
  - **单点置信度评估**：通过 LoRA 适配器微调 $M_{ext}$，结合模型概率与基于标注数据 $D_l$ 的共形预测阈值计算校准置信度：
    $$\text{conf}(t_k) = C_a(\text{Prob}_{M_{ext}+\text{LoRA}}(t_k|d_k, S_q), D_l)$$

  - **跨记录逻辑一致性检查**：定义模式相关的逻辑约束集 $C(S_q)$，包括函数依赖（如 Person_ID → Date_of_Birth）、时序约束（Admission_Time < Discharge_Time）、数值范围及外键引用完整性。系统在临时数据库中检测违反约束的元组集 $V$。

- **动态校正策略**：对低置信度（$\text{conf}(t_k) < \tau_{low}$）或逻辑违规（$t_k \in V$）的元组，根据违规类型选择策略：简单缺失采用更强 LLM 委员会重抽取；复杂逻辑冲突则提交验证与消歧子模块进行深度上下文分析或回溯检索。最终生成高质量关系数据库 $DB_q$。

### 3. 模式引导的关系推理模块（Schema-Guided Relational Reasoning）

该模块在精确构建的数据库 $DB_q$ 上直接执行查询，将复杂多跳推理转化为确定性数据库操作：

- **查询编译与优化**：推理模型 $M_{reason}$ 将查询 $q$ 编译为 SQL 查询 $Q_{SQL}$。利用 $S_q$ 中的显式连接键与关系定义，生成优化的连接查询，通过下推过滤与选择高效连接顺序提升效率：
  $$Q_{SQL}^{optimized} = F_{compile\_optimize}(q, S_q)$$

- **证据溯源与答案生成**：执行优化查询获得结果集 $R$，系统自动追溯每行数据的来源至 $DB_q$ 中的元组及原始文档块 $D_{context}$。基于 $R$ 与完整溯源链 $E$ 合成自然语言答案：
  $$a, E = F_{synthesize}(R, DB_q, D_{context})$$

### 关键技术优势

该设计通过以下机制解决 MDMEQA 的核心难题：

- **SQL 驱动的精确事实定位**：避免向量相似性检索导致的细粒度事实遗漏。
- **关系表天然支持跨文档实体连接**：通过可连接模式属性（joinable schema attributes）实现高效的跨文档实体对齐与证据链构建。
- **结构化表示缓解注意力扩散**：将多跳逻辑、连接与聚合操作卸载至确定性 SQL 引擎，避免大语言模型在长程推理中的注意力稀释与幻觉问题。

## 实验验证

该论文在 **MEBench** 与 **Loong** 两个代表性的 MDMEQA 基准测试上进行了全面评估，涵盖主实验对比与细粒度消融研究。

### 1. 实验设置

**评估数据集**
- **MEBench**：包含 4,780 个系统化构建的多实体问答实例，按推理类型分为 **Comparison**（比较）、**Statistics**（统计）、**Relationship**（关系）三类；按实体密度划分为 Set1（0-10 个实体）、Set2（11-100 个实体）、Set3（>100 个实体）。
- **Loong**：设计用于测试长上下文能力，包含 **Spotlight Locating**（精确查找）、**Comparison**（比较）、**Clustering**（聚类）、**Chain of Reasoning**（推理链）四类任务，文档长度覆盖 10K-50K、50K-100K、100K-200K、200K-250K tokens 四个层级。

**基线方法**
- **GPT-4o**：直接以完整文档或截断上下文作为输入的生成式基线。
- **GPT-4o + RAG**：标准检索增强生成框架，基于向量相似性检索相关文本块。
- **GraphRAG**：构建知识图谱（头实体-关系-尾实体三元组）并进行图检索与推理。
- **StructRAG**：动态识别适合任务的结构表示并重构文本进行推理。

**评估指标**
- **MEBench**：采用 **Accuracy**（准确率）作为主要指标；统计类子任务（方差分析、相关性分析、分布合规性）额外评估所选列与方法正确性。
- **Loong**：采用 **Avg Score**（LLM 评判的 0-100 分）与 **Perfect Rate**（Exact Match，完全匹配率）双指标。

**实现细节**
- 核心 LLM：GPT-4o、Qwen3
- 抽取模型：Mistral-7B（经 LoRA 微调）
- 推理模型：GPT-4o

### 2. 主实验结果

**MEBench 性能（表 1）**
- **整体表现**：DocSage 达到 **89.2%** 的整体准确率，较次优基线 GPT-4o + RAG（62.0%）提升 **27.2 个百分点**，较 StructRAG（61.2%）与 GraphRAG（58.6%）优势显著。
- **跨问题类型一致性**：在 Comparison（93.4%）、Statistics（90.8%）、Relationship（81.2%）三类任务上均保持领先。
- **实体密度扩展性**：当实体数量从 Set1（0-10 个）增至 Set3（>100 个）时，DocSage 准确率仅从 91.8% 微降至 87.9%（降幅 3.9%），而 GPT-4o + RAG 从 76.4% 暴跌至 41.5%（降幅 34.9%），验证了其对高实体密度场景的鲁棒性。

**Loong 性能（表 2）**
- **长文档问答**：DocSage 获得 **68.29** 的平均分与 **0.53** 的 Perfect Rate，较 GPT-4o（0.26）与 StructRAG（0.23）提升逾一倍。
- **任务特异性优势**：
  - **Spotlight Locating**：Perfect Rate 达 0.84，显著优于 GPT-4o（0.65）与 GPT-4o + RAG（0.44）。
  - **Chain of Reasoning**：Perfect Rate 0.57，较 GPT-4o（0.27）与 GraphRAG（0.23）有本质提升。
- **长度扩展性**：在最长文档设置（200K-250K tokens）下，DocSage 仍保持 0.47 的 Perfect Rate，而对比方法普遍降至 0.10 以下。

### 3. 消融实验

为验证各模块贡献，论文在 MEBench 与 Loong 上执行了系统消融（表 3、表 4）：

**关键发现**
- **结构化抽取模块（Structured Extraction）**：移除后 MEBench 整体准确率下降 **20.1 个百分点**（从 89.2% 降至 69.1%），为影响最大的组件，证明将非结构化文本转换为高保真关系数据是框架的基石。
- **模式引导推理（Schema-Guided Reasoning）**：移除后 MEBench 准确率下降 **11.9 个百分点**，验证将多跳逻辑、连接与聚合操作卸载至确定性 SQL 引擎对避免 LLM 注意力扩散的关键作用。
- **动态模式发现（Schema Discovery）**：移除后 MEBench 准确率下降 **11.1 个百分点**，表明动态推断查询特定模式对组织碎片化实体信息至关重要。
- **CLEAR 逻辑校正**：禁用跨记录逻辑一致性检查后，MEBench 准确率下降 **4.3 个百分点**，证实逻辑约束对数据质量提升的稳健性增益。
- **主动发现（ASK vs. Passive）**：采用被动模式发现替代 ASK 算法，MEBench 准确率下降 **2.9 个百分点**，说明交互式澄清提问在信息模糊场景下的细化价值。

**长文档场景验证（Loong）**
- 在 200K-250K tokens 的最长设置下，移除 Schema Discovery 导致 Chain of Reasoning 任务性能下降最为显著（-13.22 分），凸显模式发现对组织分散在超长文本中信息的极端重要性。
- 移除 Structured Extraction 对 Comparison（-9.17 分）与 Clustering（-9.20 分）任务影响最大，表明精确实体匹配与属性聚合依赖高质量的结构化表示。

## 未来工作

基于论文第6节所述局限性及框架设计，以下方向值得进一步探索：

### 1. 计算效率优化与基础模型解耦
当前 DocSage 的性能与效率高度依赖底层大语言模型（用于模式发现与抽取）的能力，且迭代式、多阶段的智能体流程带来显著计算开销。未来研究可探索：
- **轻量级模式推导**：开发无需反复调用大型 LLM 的模式发现算法，例如利用小型语言模型结合符号推理进行模式归纳。
- **增量式结构更新**：设计支持文档动态增减的增量更新机制，避免面对新文档时重新执行完整流程。
- **检索-抽取联合优化**：将向量检索与结构化抽取过程融合，减少冗余的 LLM 调用次数。

### 2. 极端噪声与矛盾文本处理
现有框架假设源文档具有基本语义连贯性与事实一致性。针对真实场景中常见的**高度嘈杂、自相矛盾或领域极度专业化**的文本（如手写病历扫描件、冲突的法庭证词），可探索：
- **矛盾检测与消解模块**：在 CLEAR 机制中引入显式的事实冲突识别与可信度加权策略，而非仅依赖逻辑一致性检查。
- **多源证据融合**：当跨文档信息冲突时，引入证据可靠性评估与基于不确定性的推理，而非简单追求逻辑一致性。

### 3. 模式发现的收敛性与完备性理论
ASK 算法通过启发式交互发现模式，但缺乏**形式化的收敛保证**与**模式完备性验证**。未来可研究：
- 模式发现过程的形式化建模，证明其在特定文档分布下的收敛条件。
- 开发模式质量评估指标，量化所发现模式对回答特定查询的充分必要性。

### 4. 动态环境与流式文档处理
当前框架针对**静态文档集合**设计。对于新闻监控、金融财报实时更新等流式场景，需扩展：
- **时态模式演化**：支持模式随时间推移的版本管理与历史追溯。
- **在线实体链接**：在文档持续流入时，维护跨文档实体对齐的增量更新机制，避免全量重计算。

### 5. 多模态 MDMEQA 扩展
当前处理对象局限于纯文本。针对包含**表格、图像、图表**的富文档集合（如企业年报、科研论文），可探索：
- 跨模态模式发现：联合推断文本与结构化表格/图像内容的统一关系模式。
- 多模态实体对齐：解决文本中实体与表格/图像中对应实体的指代消解问题。

### 6. 人在回路中的交互式验证
尽管 DocSage 提供错误保证机制，但在高风险领域（如医疗、法律），可引入**人机协同验证**：
- 将 CLEAR 机制标记的低置信度或逻辑冲突元组呈现给领域专家进行人工校验。
- 设计交互式模式修正界面，允许专家在关键步骤干预模式发现过程，提升最终答案的可信度。

## 总结

该论文针对**多文档多实体问答**（Multi-document Multi-entity Question Answering, **MDMEQA**）任务，提出了一种端到端的信息结构化智能体框架 **DocSage**，通过动态模式发现与结构化推理解决跨文档实体关系追踪难题。

### 1. 研究背景与核心挑战

MDMEQA 要求模型在分散于多个非结构化文档的实体间建立隐式逻辑连接并构建证据链。现有方法存在根本性局限：
- **标准 RAG** 依赖向量相似性检索，导致关键事实遗漏；
- **图增强 RAG** 难以高效整合跨文档的碎片化复杂关系网络，且计算成本高昂；
- **长上下文 LLM** 受限于注意力扩散（contextual dilution），在长篇文本中丢失关键实体；
- **缺乏模式感知**（schema awareness），无法系统组织分散信息，导致证据链断裂。

### 2. DocSage 框架设计

DocSage 通过三个顺序集成的核心模块，将非结构化文档集 $D$ 与查询 $q$ 转化为精确的结构化答案：

#### （1）交互式模式发现模块（Interactive Schema Discovery）
通过 **ASK 算法**（Active Schema Discovery via Knowledge-seeking Queries）动态推断查询特定的最小可连接模式 $S_q$：
- 初始生成模式假设 $S_q^0 = F_{init}(q, D_{sample})$；
- 识别实体对齐冲突、属性异常与关系缺失等不确定性信号，生成澄清问题集 $P = F_{ask}(S_q^k, D, \text{Uncertainty Signals})$；
- 基于检索证据迭代更新模式 $S_q^{k+1} = F_{update}(S_q^k, A(P, D))$，直至收敛。

#### （2）逻辑感知结构化抽取模块（Logic-Aware Structured Extraction）
利用 **CLEAR 机制**（Cross-record Logic Enforcement for Accuracy Reinforcement）将文本转换为高保真关系表：
- **单点置信度校准**：通过 LoRA 适配器微调抽取模型，结合共形预测计算校准置信度 $\text{conf}(t_k) = C_a(\text{Prob}_{M_{ext}+\text{LoRA}}(t_k|d_k, S_q), D_l)$；
- **跨记录逻辑一致性检查**：强制执行函数依赖、时序约束、数值范围及外键完整性等约束 $C(S_q)$；
- 对低置信度或逻辑违规元组触发动态校正，生成高质量数据库 $DB_q$。

#### （3）模式引导的关系推理模块（Schema-Guided Relational Reasoning）
在结构化数据上执行确定性推理：
- 将查询编译为优化 SQL $Q_{SQL}^{optimized} = F_{compile\_optimize}(q, S_q)$，利用模式感知实现高效连接与过滤下推；
- 执行查询后追溯证据来源，合成带完整溯源链 $E$ 的自然语言答案 $a$。

### 3. 关键技术优势

- **SQL 驱动的精确事实定位**：避免向量检索的粗粒度选择；
- **关系表天然支持跨文档实体连接**：通过可连接模式属性（joinable schema attributes）简化多跳证据链构建；
- **结构化表示缓解 LLM 注意力扩散**：将复杂逻辑运算卸载至数据库引擎，避免长程推理中的幻觉与信息丢失。

### 4. 实验验证

在 **MEBench** 与 **Loong** 两个基准上的评估表明：
- **准确率提升**：在 MEBench 上达到 89.2% 的整体准确率，较长上下文 LLM 与 RAG 基线分别提升 **27.2%** 与 **27%**；
- **扩展性优势**：在实体数量超过 100 的 Set3 场景中，DocSage 准确率仅从 91.8% 微降至 87.9%，而 GPT-4o + RAG 从 76.4% 暴跌至 41.5%；
- **长文档鲁棒性**：在 Loong 的 200K-250K tokens 最长设置下，保持 0.47 的 Perfect Rate，对比方法普遍低于 0.10。

消融研究验证了各模块贡献：**结构化抽取模块**（移除导致 -20.1% 性能下降）与**模式引导推理**（-11.9%）为核心组件，**动态模式发现**（-11.1%）与 **CLEAR 逻辑校正**（-4.3%）提供重要稳健性增益。

### 5. 结论

DocSage 验证了以动态结构归纳为核心的智能体工作流在处理碎片化、模式稀缺的多文档数据时的有效性，通过将非结构化文本转化为查询特定的关系表示，实现了精确的跨文档实体对齐、可验证的多跳推理与显著的准确性提升。
