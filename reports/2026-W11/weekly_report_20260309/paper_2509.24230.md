# ELHPlan: Efficient Long-Horizon Task Planning for Multi-Agent Collaboration

**arXiv**: [2509.24230](https://arxiv.org/abs/2509.24230) · [PDF](https://arxiv.org/pdf/2509.24230)  
**领域**: Agent  
**作者**: Ling, Wang, Fan, Lam, Hu  
**综合评分**: 8.36  （novelty: 9.0 · method: 8.5 · evidence: 8.5 · clarity: 8.0）

## 摘要

> 本文提出了一种名为ELHPlan的高效长时域任务规划框架，用于解决基于大语言模型的多智能体协作中开放环规划与迭代规划之间的权衡问题。该方法通过引入绑定子目标意图的动作链作为基本规划单元，采用构建、验证、精炼、执行的循环流程，在保持任务成功率的同时显著降低了计算开销。实验表明，该方法在TDW-MAT和C-WAH基准测试中仅需消耗当前最优方法30-40%的令牌量，为LLM驱动的多智能体规划系统建立了新的效率-效果前沿。

## 详细分析

> **社区热度**: ⭐ 3 (来自 papers.cool)

## 问题定义

论文针对“长时域多智能体协作任务规划”中存在的两大瓶颈——  
1. 声明式方法在动态、部分可观测环境下适应性差；  
2. 迭代式方法随团队规模与任务长度呈指数级增长的推理延迟与 token 开销——  

提出核心问题：  
> 如何在保持迭代规划灵活性的同时，显著降低多智能体场景下的 token 消耗与推理延迟，并高效共享动作意图以避免冲突与重复？

为此，作者提出 ELHPlan 框架，以“动作链（Action Chain）”作为最小规划原语，将动作序列与对应的子目标意图显式绑定，通过“构造-验证-精炼-执行”的循环机制，在无需全量重规划的前提下实现长时域协作，从而重新划定“效率-效果”前沿。

## 相关工作

相关研究可归纳为两条主线：单智能体任务规划与多智能体协作。以下按主题梳理代表性文献，并指出与 ELHPlan 的差异。

- **A. LLM 单智能体任务规划**
  1. **声明式一次性规划**  
     - LLM+P (Zhao et al., NeurIPS 2023)  
     - DELTA (Liu et al., arXiv 2024)  
     特点：将自然语言转为 PDDL/场景图，一次性生成完整计划；需全局可观测，动态环境适应性差。  
  2. **迭代式局部规划**  
     - ReAct (Yao et al., ICLR 2023)  
     - ADaPT (Prasad et al., NAACL 2024)  
     - LLM-BT (Zhou et al., arXiv 2024)  
     特点：每步或每短 horizon 查询 LLM，灵活但 token 开销大。  
  3. **宏动作/层次化抽象**  
     - Macro actions (Liu et al., AAMAS 2024)  
     - ChatHTN (Muñoz-Avila et al., NeSy 2025)  
     特点：把原始动作封装为高层步骤，减少调用次数；但未显式携带“意图”供多智能体共享。

- **B. LLM 多智能体协作**
  1. **去中心化对话协商**  
     - ROCO (Zhao et al., arXiv 2023)  
     - CAMEL (Li et al., NeurIPS 2024)  
     特点：依赖自然语言广播，语义丰富但 token 成本与延迟高。  
  2. **隐式意图推理**  
     - ProAgent (Zhang et al., AAAI 2024)  
     特点：通过观察推测同伴意图，易因误解导致冲突。  
  3. **中心化协调器**  
     - Smart-LLM (Kannan et al., IROS 2024)  
     - REBEL (Gupte et al., arXiv 2024)  
     特点：统一分配任务，减少通信；但通常一次性规划，动态重调度能力弱。  
  4. **结构化验证与经验复用**  
     - REVECA (Seo et al., arXiv 2024)  
     - LEAPlan (本文对比基线)  
     特点：引入轨迹级验证或共享记忆，仍采用逐步迭代方式，token 随步数线性增长。

- **与 ELHPlan 的核心区别**  
  上述工作要么“一次性规划+无意图显式共享”，要么“逐步迭代+高频率 LLM 查询”。ELHPlan 首次将“动作序列+子目标意图”封装为原子单元（Action Chain），在中心化共享内存下实现链级构造、冲突前验证与局部精炼，从而把迭代重规划次数与 token 消耗降低一个量级，同时保留动态环境下的适应性。

## 解决方案

论文将“长时域多智能体规划”拆解为**「如何少调用 LLM，却仍能快速适应动态环境并避免冲突」**这一核心矛盾，提出三条关键技术：

1. 新原语：Action Chain  
   把「动作序列 + 子目标意图」一次性生成，作为最小规划单元；意图字段供同伴直接读取，无需额外推理或对话，天然消除意图误解。

2. 三阶段循环架构  
   - **构造**：单条 LLM 调用即输出整条 Action Chain，链长随子目标复杂度自适应，并在高不确定处插入 `replan` 占位符。  
   - **验证**：执行前仅对链头动作做可行性检查与冲突检测，O(1) 时间复杂度。  
   - **精炼**：若验证失败，触发三种局部机制（Chain Refinement / Conflict Resolution / Chain Insertion），仅重写受影响链段，避免全量重规划。

3. 共享内存与中心化协调  
   所有 agent 的观测、链意图与历史经验写入同一上下文，规划器一次 prompt 即可同时生成多 agent 的 Action Chains，进一步压缩 token 用量。

通过「链级生成 + 局部精炼」，ELHPlan 把迭代重规划次数从「步级」降到「链级」，在 TDW-MAT 与 C-WAH 上仅消耗 SOTA 方法 24 % 的 token，却保持可比任务成功率，从而重新划定效率-效果前沿。

## 实验验证

实验在两条公开长时域室内仿真基准上展开，共 34 个任务、覆盖 10 种 LLM-backbone，从「任务效果」「资源效率」「模块贡献」三个维度系统评估。

1. 主实验  
   - **环境**  
     – TDW-MAT：24 任务×10 子目标，步限 3 000。  
     – C-WAH：10 任务×3-5 子目标，步限 150。  
   - **指标**  
     通用：Transport Rate / Move Distance / Simulation Steps  
     新增：Token Consumption (TC) 与 Inference Time (IT)  
   - **对照**  
     CoELA、REVECA、LEAPlan，均更换 3-4 种 LLM（GPT-4o、GPT-3.5、Llama3.1、4o-mini）。  
   - **结果**  
     ELHPlan-GPT-4o 在两项环境中 TC 降低 64-75 %，IT 降低 74-91 %，任务成功率与最佳基线持平或略低（差距 <3 %），实现新的「效率-效果」前沿。

2. 消融实验（C-WAH, gpt-4o-mini）  
   依次移除 Action Chain、链级精炼、意图绑定、主动 replan 占位符四组件，观测相对全框架的退化：  
   - 无 Chain：TC ↑79 %，IT ↑182 %  
   - 无链级精炼：SS ↑16 %，TC ↑9 %  
   - 无意图绑定：SS ↑16 %，IT ↑118 %  
   - 无主动 replan：SS ↑25 %  
   量化验证各模块对 token 节省与任务效率的具体贡献。

3. 跨模型稳定性测试  
   同一框架切换 Llama3.1→GPT-4o，ELHPlan 的 TR 波动 <6 %，TC 下降 137 %；对比 CoELA 波动 34 %，显示其对大模型依赖更低。

4. 定性轨迹分析  
   可视化图 1/4 展示在同等任务下，ELHPlan 用 22 882 token 探索更大区域，而 CoELA 用 23 042 token 出现重复路径，直观说明 token 节省与空间覆盖优势。

## 未来工作

- **1. 亚秒级推理**  
  当前链级生成仍受限于自回归 LLM 的串行解码。可探索：  
  - 针对 Action Chain 的轻量级规划专用小模型（<1 B 参数）蒸馏与微调；  
  - 投机解码、并行前缀融合或早期退出机制，把单链生成延迟压到 100 ms 以内，满足实时机器人闭环。

- **2. 层级动作链压缩**  
  室内任务存在大量重复「go-to→grasp→go-to→place」模式。可引入：  
  - 基于成功链的自动“宏操作”抽象，形成可复用技能库；  
  - 在线聚类与频次阈值触发，动态把高频子链合并为单步高层动作，进一步降低调用次数。

- **3. 意图空间的显式度量学习**  
  目前意图仅用自然语言描述，相似度靠 LLM 隐式判断。可：  
  - 利用对比学习将意图语句嵌入共享语义空间，实现快速冲突预筛选（<O(n²)）；  
  - 引入能量模型或余弦 margin，使“冲突意图”在嵌入空间相距更远，减少误检。

- **4. 强化链内占位符策略**  
  `replan` 位置固定由启发式规则决定。可：  
  - 把「何时插入」建模为序列标记决策问题，用强化学习（环境不确定度作为状态）学习最优插入策略，降低过度保守导致的链碎片化。

- **5. 异构多机器人扩展**  
  现有实验仅考虑同构 agent。后续可：  
  - 在 Action Chain 中增加 `capability_mask` 字段，显式声明所需传感器/执行器；  
  - 引入能力-任务二分匹配层，使中心化规划器直接输出“谁适合哪条链”，支持异构车队一键部署。

- **6. 物理世界在线适应**  
  仿真到真实存在动态误差与遮挡差异。可：  
  - 将链验证模块升级为「可微检查器」，利用梯度反馈微调链参数（如目标坐标偏移），实现毫米级修正；  
  - 结合视觉-语言-动作 (VLA) 模型，把 Action Chain 作为高层指令，低层由 VLA 输出连续控制，形成两层协同。

- **7. 人类偏好对齐**  
  偶尔出现违反约束或幻觉动作。可：  
  - 在精炼阶段引入人类-在环反馈，用 DPO 或 KTO 对规划 LLM 进行偏好微调，提高安全性与指令遵循度；  
  - 建立「约束违规」自动标注流水线，持续扩充负例库，实现自我改进循环。

- **8. 大规模场景并行化**  
  当 agent 数量 >50 时，中心化 prompt 长度线性增长。可：  
  - 采用「分簇-合并」范式：先按空间邻近度分簇，簇内链冲突局部求解，再跨簇做二次一致性检查；  
  - 利用图神经网络对冲突图进行嵌入，提前预测高冲突区域，实现增量式链更新而非全局重生成。

## 总结

论文提出 **ELHPlan**，一套面向**长时域多智能体协作**的**高效 token 规划框架**，核心思想与贡献如下：

---

### 1 问题背景
- 声明式规划：一次性生成完整计划，**不适应**动态、部分可观测环境。  
- 迭代式规划：逐步调用 LLM，**token 开销随步数与 agent 数线性爆炸**。  
- 多 agent 还需共享“动作意图”，现有显式对话或隐式推理均**昂贵且易误解**。

---

### 2 关键原语：Action Chain
- 最小规划单元 = **动作序列 + 显式子目标意图**（JSON 结构）。  
- 一次 LLM 调用生成整条链，链长自适应；在高不确定处插入 `replan` 占位符。  
- 同伴直接读取意图字段，**零额外推理**即可检测冲突与冗余。

---

### 3 框架流程（三阶段循环）
1. **构造**：中心化规划器基于共享内存，一次性输出各 agent 的 Action Chain。  
2. **验证**：  
   - 链头动作若 = `replan` → 触发 Chain Insertion；  
   - 否则检查可行性（预条件、动态动作空间）；  
   - 发现冲突 → 触发 Conflict Resolution。  
3. **精炼**：  
   - Chain Refinement：替换/删除不可行动作，保留原意图；  
   - Conflict Resolution：重写冲突双方整条链，消除资源争用；  
   - Chain Insertion：用最新观测生成新链替代 `replan`。  

循环直至所有子目标完成。

---

### 4 效率指标
首次引入 **Token Consumption (TC)** 与 **Inference Time (IT)** 作为多 agent 协作的核心评价维度，与任务成功率并列。

---

### 5 实验结果
| 环境 | 成功率 | TC 降幅 | IT 降幅 |
|------|--------|---------|---------|
| TDW-MAT | 与最佳基线持平 | −64 % | −74 % |
| C-WAH | 与最佳基线持平 | −75 % | −91 % |

- 仅消耗 SOTA 方法 **24 % token** 即实现可比任务性能。  
- 跨 4 种 LLM 的波动 <6 %，展现出**模型无关稳定性**。

---

### 6 消融验证
移除 Action Chain、链级精炼、意图绑定、主动 replan 任一组件，token 或步数均显著恶化，证明各模块对效率与效果缺一不可。

---

### 7 局限与未来
- 链生成仍慢于人类，需蒸馏轻量规划模型；  
- 偶发约束违规，可引入 RLHF 进一步对齐；  
- 将扩展到异构机器人、真实物理部署与大规模并行场景。

---

**一句话总结**：ELHPlan 用“一次生成整条意图绑定动作链 + 局部精炼”替代“步步迭代”，在长时域多 agent 任务中重新划定**高效-高成功**的新边界。
