# CORAL: Towards Autonomous Multi-Agent Evolution for Open-Ended Discovery

**arXiv**: [2604.01658](https://arxiv.org/abs/2604.01658) · [PDF](https://arxiv.org/pdf/2604.01658)  
**领域**: Agent  
**作者**: Qu, Zheng, Zhou, Yan, Tang, Ong, Hong, Zhou 等 17 人  
**综合评分**: 8.44  （novelty: 9.0 · method: 8.5 · evidence: 9.0 · clarity: 7.5）

## 摘要

> 本文提出了一种名为CORAL的自主多智能体进化框架，用于解决开放式发现问题。该框架通过引入长期运行的智能体、共享持久内存、异步多智能体执行和基于心跳的干预机制，取代了传统的固定启发式规则和硬编码探索方法。在多个数学、算法和系统优化任务上，CORAL在10个任务上取得了新的最先进结果，改进率比固定进化搜索基线高出3-10倍，且所需评估次数更少。在Anthropic的内核工程任务中，四个协同进化的智能体将最佳已知分数从1363周期提升至1103周期。论文提供了详细的机制分析，展示了知识重用和多智能体探索与通信带来的收益。代码已在GitHub上开源。

## 详细分析

## 问题定义

这篇论文试图解决**现有大语言模型（LLM）驱动进化方法在开放式发现问题中过度依赖固定启发式与硬编码控制规则**的局限性，具体可分解为以下核心问题：

### 1. 固定进化搜索的自主性缺失
现有方法（如 FunSearch、AlphaEvolve）将 LLM 嵌入由外部 predetermined 规则控制的进化循环：
- **检索（Retrieve）**与**更新（Update）**阶段由固定启发式（如 MAP-Elites、岛屿模型）主导，智能体无法自主决定.inspect 哪些证据、何时进行中间验证、如何响应失败或保存可复用知识；
- **提议（Propose）**阶段通常仅为单次前向生成，缺乏对搜索方向的动态反思与调整能力。

这种"刚性控制"限制了智能体在开放式问题中根据反馈自主调整搜索策略的能力。

### 2. 多智能体系统的垂直扩展局限
现有多智能体系统多采用**垂直扩展**范式：
- 依赖人类预先分解任务、分配专业化角色、定义固定通信拓扑（如 AI Scientist、AI Co-Scientist）；
- 假设最优分解与交互结构事先已知，这对目标函数未知、解空间开放的开放式问题构成严格限制。

### 3. 知识积累的碎片化
现有方法缺乏支持长期搜索的**共享持久记忆**机制：
- 智能体状态通常无状态（stateless），跨步骤记忆不连续；
- 缺乏系统化的知识外化（externalization）与复用机制，导致历史发现的洞察难以跨迭代、跨智能体传承。

### 核心解决方案
论文提出 **CORAL（自主多智能体进化框架）**，通过以下机制解决上述问题：
- **自主决策**：将检索、提议、评估调度、知识存储等决策权下放给智能体本身；
- **水平并行**：通过共享持久记忆（attempts/notes/skills）实现异步多智能体协调，支持自发探索多样性、技术扩散与共识涌现，无需预定义通信协议；
- **长期自主性**：引入心跳机制（heartbeat-based interventions）实现周期性反思、知识整合与停滞重定向，支撑长时程搜索。

简言之，该研究致力于**将开放式发现从"固定算法驱动的搜索"范式转变为"自主智能体驱动的进化"范式**，使 LLM 智能体能够像研究团队一样自主探索、反思、协作并持续积累知识。

## 相关工作

这篇论文的相关研究主要围绕三个维度展开，涵盖从固定进化搜索到自主智能体、再到多智能体协作的技术谱系：

### 1. LLM 驱动的进化搜索（LLM-Driven Evolutionary Search）
该方向将 LLM 嵌入评估器引导的进化循环作为变异算子，但**保留固定的外部控制逻辑**：

- **奠基工作**：FunSearch（Romera-Paredes et al., 2024）首次引入该范式；AlphaEvolve（Novikov et al., 2025）将其扩展到完整代码库并结合 MAP-Elites 算法。
- **搜索策略优化**：后续研究通过自适应采样、基于岛屿的架构、帕累托选择（Sharma, 2025; Lange et al., 2025; Khrulkov et al., 2025; Assumpção et al., 2026; Yan et al., 2026; Agrawal et al., 2025）以及元进化（AdaEvolve、EvoX）来改进搜索编排。
- **生成器增强**：测试时微调（Wang et al., 2025; Yuksekgonul et al., 2026）或从求解器反馈构建经验库（Ouyang et al., 2025b; Kong et al., 2025）。

**与 CORAL 的区别**：上述系统遵循固定管道——通过预定启发式选择父代、构建提示、调用 LLM 产生变异，**LLM 对下一步探索什么没有决策权**。

### 2. 自主 LLM 智能体（Autonomous LLM Agents）
该方向赋予 LLM 智能体在开放任务中的自主执行能力，但**侧重一次性任务完成而非持续优化**：

- **自主编码**：智能体在沙箱环境中导航代码库、执行代码和迭代调试（Yang et al., 2024; Wang et al., 2024）。
- **自动化研究**：AI Scientist（Lu et al., 2024）实现从构思到论文撰写的完整研究周期自动化。
- **自我改进机制**：语言自我反馈（Shinn et al., 2023; Madaan et al., 2023）、推理与工具使用交织（Yao et al., 2023）、学习记忆巩固（Zhou et al., 2026; Yu et al., 2026）。
- **演化智能体**：近期立场论文主张将部署时适应提升为自主进化智能体（Gao et al., 2025）。

**与 CORAL 的区别**：这些系统展示了开放式任务完成的强大能力，但**未针对持续的、目标驱动的优化循环设计**，缺乏在进化过程中积累和利用知识的机制。

### 3. 多智能体协作（Multi-Agent Collaboration）
该方向探索通过结构化通信或涌现合作解决复杂任务，但**缺乏进化过程中的状态共享**：

- **垂直分解**：通过角色分配和结构化通信分解复杂任务（Wu et al., 2023; LangChain, 2024; Qian et al., 2024; Hong et al., 2024）。
- **涌现合作**：通过角色扮演和动态群体形成探索自发合作行为（Li et al., 2023; Chen et al., 2024）。
- **现有进化系统的局限**：FunSearch 和 AlphaEvolve 中的并行性仅限于并发运行多个**无状态**评估工作器，步骤间无记忆共享。

**与 CORAL 的区别**：CORAL 引入**长期存在、有状态的智能体**，通过共享持久记忆（评分的尝试、笔记、技能）进行**异步间接通信**，实现技术扩散、自发共识和交叉引用等涌现行为，无需硬编码协调协议。

## 解决方案

论文通过提出 **CORAL（面向开放式问题的自主多智能体进化框架）** 解决上述局限，其核心在于将决策权从固定算法转移到自主智能体，并通过特定机制支持长期、并发的知识积累。具体解决方案包括以下层面：

### 1. 范式转变：从固定搜索到自主多智能体进化
CORAL 首先完成了从"固定进化搜索"到"自主进化"的范式转换（图1，第3.2节）：

- **自主单智能体进化**：将原本由外部硬编码控制的 **RETRIEVE**（检索）与 **UPDATE**（更新）阶段下放给智能体自主决策。智能体自行决定：检查哪些历史证据、何时运行本地验证、如何响应失败、以及将何种知识外化保存。
- **自主多智能体进化**：扩展至多个智能体异步运行，通过共享持久记忆协调，无需预定义角色或通信拓扑。智能体通过写入和读取共享工件（尝试、笔记、技能）实现间接协作，从而支持探索多样性、技术扩散和自发共识等涌现行为。

### 2. 共享持久记忆（Shared Persistent Memory）
CORAL 将共享记忆实现为**文件系统结构**（第3.3节，附录C.4），通过符号链接挂载到各智能体工作区，包含三个核心知识库：

- **`attempts/`**：记录所有历史评估与解决方案，智能体可浏览以理解高性能方案并检索代码进行比较。
- **`notes/`**：以 Markdown 文件形式存储观察、学习与反思，支持层次化组织（如 `notes/synthesis/`、`notes/open-questions.md`）。智能体可主动整理、分类和交叉引用。
- **`skills/`**：存储可复用的程序、工具与实现模式（包含自然语言描述 `SKILL.md` 及可执行工件），支持跨任务迁移。

该设计允许渐进式信息披露，智能体通过 CORAL CLI 工具（`coral log`、`coral show` 等）或 Bash 工具直接访问，实现知识的持续积累与复用。

### 3. 异步多智能体组织（Asynchronous Multi-Agent Organization）
CORAL 采用**无中心协调**的多智能体架构（第3.3节，附录C.6）：

- **工作区隔离**：每个智能体在独立的 Git worktree（分支）中运行，通过 `.gitignore` 防止意外提交共享内存，确保代码状态互不干扰。
- **间接协调**：智能体不通过消息传递直接通信，而是通过**共享持久记忆**进行协调。智能体 $i$ 在时间 $t$ 产生的工件 $W_t^{(i)}$ 写入共享内存 $M$，后续被智能体 $j$ 检索为其工作上下文 $\hat{M}_t^{(j)}$ 的一部分。
- **水平并行**：多个智能体并行探索解空间的不同区域，通过共享内存自发地"借鉴"彼此的发现，无需硬编码的父代选择或交叉算子。

### 4. 心跳干预机制（Heartbeat-Based Interventions）
为避免智能体陷入局部最优或遗忘知识积累，CORAL 引入**心跳机制**（第3.3节，附录C.5），类似于定时提醒应用，包含三种干预类型：

- **每轮反思（Per-iteration Reflection）**：每轮评估后触发，强制智能体记录具体结果、分析意外现象、评估置信度并规划下一步实验，促进即时知识外化。
- **周期性整合（Periodic Consolidation）**：每固定次数（如10次）评估后触发，要求智能体综合共享知识库，创建合成笔记（synthesis notes）、更新关联图谱（connections map）与开放问题列表（open-questions），并将验证有效的技术提炼为技能。
- **停滞触发的重定向（Stagnation-Triggered Redirection）**：当连续多轮（如5次）无改进时触发，强制智能体诊断当前方法的理论极限，研究领先尝试的核心思想，并**转向根本不同的算法家族或问题表征**，或从最优基础重新构建（通过 `coral checkout` 重置）。

### 5. 执行安全保障（Execution Safeguards）
为支撑上述自主性，CORAL 提供多重实用保障（附录C.7）：

- **评估器隔离**：评估器代码置于 `.coral/private/`（对智能体不可见），防止智能体通过检查评分逻辑进行奖励黑客（reward hacking）。
- **资源管理**：为评估调用设置硬超时（默认300秒），防止无限循环；通过进程管理记录 PID，支持优雅关闭（SIGINT → SIGTERM → SIGKILL）与死智能体重启。
- **会话持久化**：保存智能体会话 ID 至 `.coral/public/sessions.json`，支持 `coral resume` 恢复长时程运行，确保进化过程的连续性。

通过上述机制，CORAL 实现了"全自主"（Full Autonomy）的进化范式：智能体自主控制检索、提议、评估调度与知识更新，多智能体通过共享内存异步协作，显著提升了开放式发现问题中的搜索效率与最终性能。

## 实验验证

论文在数学优化、算法优化和系统优化三类任务上开展了系统性实验，涵盖**单智能体自主进化**、**多智能体协同进化**、**消融研究**及**轨迹分析**四个层面。具体实验设置如下：

### 1. 实验任务与基准
#### 任务套件
- **数学与系统优化基准**（共11项）：
  - *数学优化*（6项）：Circle Packing、Signal Processing、Erdős Minimum Overlap、MMD-16-2、MMD-14-3、3rd-Autocorrelation Inequality
  - *系统优化*（5项）：EPLB（Expert-Parallel Load Balancing）、PRISM（GPU Placement）、LLM-SQL、Transaction Scheduling、Cloudcast

- **压力测试任务**（2项）：
  - *Anthropic Kernel Engineering*：VLIW SIMD 树遍历内核优化，基线147,734周期，此前最优1,363周期
  - *Polyominoes Packing*：多格拼板紧密排列问题，Frontier-CS基准中最难的172个问题之一

#### 对比基线
- **OpenEvolve**（Sharma, 2025）：基于AlphaEvolve的开源实现，采用静态精英种群
- **ShinkaEvolve**（Lange et al., 2025）：基于bandit的自适应采样
- **EvoX**（Liu et al., 2026a）：元进化搜索策略（最强基线）

### 2. 单智能体实验（第4.2节，表1）
**目的**：验证自主进化相对固定进化搜索的优越性。

- **设置**：所有方法使用相同种子程序、评估器与预算（3小时墙钟时间或100轮迭代，取较长者）；CORAL运行时长取所有基线中的最短时长以保证公平。
- **模型**：Claude Code + Claude Opus 4.6。
- **指标**：
  - **最终得分**（Final Score）：预算内最优得分
  - **改进率**（Improvement Rate）：产生改进的评估占比
  - **评估次数**（# Evals）：达到最终得分所需评估数

**关键结果**：
- CORAL在全部11项任务中取得最优最终得分，**8项刷新SOTA**。
- 改进率比固定搜索基线高 **3–10倍**（如Erdős Overlap：36.8% vs 27.8%）。
- 评估效率提升显著，通常仅需 **5–20次**评估即可收敛，而基线需60–100次。

### 3. 多智能体协同进化实验（第4.3节，表2）
**目的**：验证水平并行（多智能体）相对单智能体的扩展性。

- **设置**：4个智能体异步运行，共享持久记忆；与单智能体CORAL及"独立运行取最优"（Best-of-4 Independent）对比。
- **模型**：除主要使用Claude Opus 4.6外，另使用**开源栈**（MiniMax M2.5 + OpenCode）验证泛化性。
- **关键结果**：
  - **Kernel Engineering**：4智能体将最优周期从1,363推至**1,103**（18.3%提升），单智能体止步于1,350。
  - **Polyominoes**：得分从80.2提升至84.2（5.0%提升）；启用网络搜索后达**89.4%**覆盖率，超越此前SOTA（87%）。
  - **开源模型验证**：在数学与系统套件上，4智能体在多数任务中优于单智能体，证明增益源于协同机制而非特定模型能力。

### 4. 消融实验（第4.4.3节，表3）
**目的**：分离知识积累与多智能体协同的因果贡献。

| 消融维度 | 任务 | 关键发现 |

| **知识积累** | Kernel Engineering | 禁用笔记与技能创建后，周期从1,350退化至1,601（**18.6%性能下降**） |

### 5. 轨迹分析（第4.4节，附录B.2）
**目的**：解释自主进化有效性的机制。

- **本地验证**（Local Verification）：分析显示，在Kernel Engineering等涉及编译代码的任务中，**57%**的尝试在提交外部评估前进行本地测试，本地测试后的改进率（47%）显著高于平均水平（43%）。
- **知识积累**（Knowledge Accumulation）：
  - 在标准任务中，智能体每尝试创建0.05个知识工件，知识访问带来的改进率提升仅2个百分点。
  - 在高级任务（Kernel Engineering、Polyominoes）中，知识创建密度达**0.55–0.68**个/尝试，知识访问的改进率达**55%**（Kernel Engineering）与**38%**（Polyominoes）。
- **跨智能体信息转移**（Cross-Agent Transfer）：
  - Kernel Engineering中，**36%**的尝试使用其他智能体的提交作为父代，其改进率（17%）显著高于平均水平（9%）；**66%**的新纪录源自跨智能体父代。
  - Polyominoes中，**87%**的轮次引用了其他智能体提交的知识（通过笔记/技能）。
- **探索多样性**：通过Jaccard相似度计算策略关键词重叠，Kernel Engineering中智能体间平均重叠仅0.43，Polyominoes仅0.31，表明各智能体探索了不同的解空间区域。

### 6. 实验环境补充（附录E）
- **硬件**：数学与系统任务在CPU实例运行；压力测试任务（Kernel Engineering、Polyominoes）亦在CPU运行（评估为模拟而非实际GPU执行）。
- **成本**：单智能体3小时运行约$30–60 USD（Claude Opus 4.6）；多智能体成本线性增长，但因改进率更高，单位改进成本更低。
- **复现性**：所有实验均进行4次独立运行取平均；评估器代码已修正原始ADRS基准中的若干错误（如PRISM的失败案例静默跳过、Txn Sched的无效调度给正分等，详见附录D.3）。

## 未来工作

基于论文的局限性分析与实验发现，未来研究可从以下维度深入探索：

### 1. 轻量化模型与边缘部署
当前 CORAL 依赖前沿大模型（如 Claude Opus 4.6）处理复杂编码工作流，难以在本地设备部署。**未来可探索**：
- 针对自主进化任务微调专用的小模型（如 7B–13B 参数规模），在保持决策能力的同时降低 API 成本与延迟；
- 开发模型量化与蒸馏策略，使多智能体进化能够在资源受限环境（如单 GPU）中持续运行。

### 2. 异质性多智能体的涌现行为
现有框架中所有智能体初始化相同、访问信息对称，缺乏**引导异质性**（bootstrapped heterogeneity）。**潜在研究方向**包括：
- 为不同智能体注入特定角色（如"架构师"、"验证者"、"破坏者"）或私有信息，模拟真实研究团队的认知多样性；
- 探索基于遗传算法的智能体"性格"进化，使行为多样性本身成为进化对象；
- 研究异质性对知识扩散速度与搜索覆盖率的定量影响。

### 3. 评估器的协同进化
当前设定假设评估器是静态且明确指定的，但许多开放式问题（如科学假设验证、艺术创作）的评估标准本身模糊或难以形式化。**未来工作**可探索：
- **评估器-求解器协同进化**：智能体在优化解决方案的同时，迭代改进评估协议（如通过对抗性训练发现评估盲点）；
- 引入人类反馈循环（Human-in-the-Loop），使评估标准在多智能体讨论中动态协商确定；
- 开发"元评估"机制，自动检测评估器中的偏差或漏洞（如防止智能体利用评估器缺陷进行奖励黑客）。

### 4. 知识表示与记忆架构优化
CORAL 采用文件系统作为共享记忆，虽具备可解释性，但存在检索效率瓶颈。**可改进方向**：
- 将非结构化笔记（Markdown）与结构化知识图谱结合，支持基于语义相似度的自动关联（而非依赖人工整理的 `connections.md`）；
- 实现分层记忆架构：工作记忆（短期上下文）、情节记忆（历史尝试）、语义记忆（蒸馏后的技能），并研究其最优整合策略；
- 探索向量数据库与符号记忆的混合检索，支持跨任务的知识迁移。

### 5. 理论分析框架的构建
论文中的实证分析揭示了知识复用与本地验证的关联性，但缺乏理论刻画。**研究空白**包括：
- 建立数学模型量化"自主检索"相对于"固定检索"的样本复杂度优势；
- 分析多智能体系统中信息转移的最优拓扑：完全共享（如 CORAL）vs. 有限通信（如群体智能中的局部交互）；
- 研究心跳机制（heartbeat）的最优触发策略：基于固定间隔 vs. 基于不确定性估计的自适应干预。

### 6. 安全、对齐与可控性
随着智能体自主性增强，风险也随之增加（附录 A）：
- **奖励黑客的防御**：当前 safeguards 为静态隔离（如隐藏评估器代码），未来需开发动态检测机制，识别智能体对评估器的对抗性适应；
- **目标漂移监控**：长期自主运行中，智能体可能偏离原始任务目标，需设计基于元认知的"目标对齐检查点"；
- **可解释性工具**：开发可视化工具追踪多智能体系统中的决策归因（如哪个智能体的哪个笔记导致了关键突破）。

### 7. 跨领域泛化与科学发现
- 将 CORAL 应用于**实验科学**（如化学合成、材料设计），其中评估涉及物理世界交互（机器人实验），需解决异步延迟与成本问题；
- 探索**开放式生成任务**（如游戏设计、数学猜想提出），其中"最优解"不存在，需重新定义适应度函数为"新颖性 + 质量"的多目标优化。

这些方向共同指向一个核心问题：**如何在提升智能体自主性的同时，保持系统的可控性、安全性与计算效率**。

## 总结

本文介绍了 **CORAL（面向开放式发现的自主多智能体进化框架）**，旨在解决现有大语言模型（LLM）驱动进化方法过度依赖固定启发式规则、缺乏自主性的问题。以下是论文的主要内容：

### 1. 研究动机与问题定义
现有 LLM-based 进化系统（如 FunSearch、AlphaEvolve）采用**固定进化搜索**范式：由外部硬编码算法控制检索、更新与父代选择，LLM 仅作为被动变异算子。这种刚性控制限制了智能体根据反馈自主调整搜索策略的能力。此外，现有多智能体系统依赖人类预定义的角色与通信拓扑，难以适应目标未知的开放式问题。

### 2. CORAL 框架的核心范式
论文提出**自主多智能体进化**范式，将进化过程的控制权从固定算法下放给智能体自身：

- **自主单智能体**：智能体自主决定检索何种证据、何时进行本地验证、如何响应失败、以及将何种知识外化保存。
- **自主多智能体**：多个智能体异步运行，通过**共享持久记忆**间接协调，无需预定义角色或通信协议，实现探索多样性与知识扩散。

### 3. 关键技术机制
CORAL 通过三项核心机制实现上述范式：

- **共享持久记忆（Shared Persistent Memory）**：以文件系统形式组织，包含：
  - `attempts/`：记录历史评估与解决方案；
  - `notes/`：存储观察、反思与中间发现；
  - `skills/`：保存可复用的程序与工具模式。
  智能体通过符号链接访问共享内存，实现知识的跨时间、跨智能体积累。

- **异步多智能体组织**：各智能体在隔离的 Git worktree 中独立运行，通过写入/读取共享内存进行间接协作。这种"水平并行"允许智能体自发探索不同解空间区域，并通过知识工件（笔记、技能）实现技术扩散。

- **心跳干预（Heartbeat-Based Interventions）**：周期性触发三种干预：
  - *每轮反思*：强制记录实验观察与下一步计划；
  - *周期性整合*：要求综合知识库、提炼技能、更新关联图谱；
  - *停滞重定向*：当陷入局部最优时，强制切换算法家族或问题表征。

### 4. 实验验证与结果
论文在数学优化（6项）、系统优化（5项）及两项压力测试任务上评估 CORAL：

- **单智能体性能**：在全部 11 项基准任务中取得最优最终得分，其中 8 项刷新 SOTA。相比固定进化基线（OpenEvolve、ShinkaEvolve、EvoX），改进率提高 **3–10 倍**，达到相同得分所需评估次数减少 **3–20 倍**。

- **多智能体增益**：在 Anthropic Kernel Engineering 任务中，4 个协同智能体将最优周期从 1,363 优化至 **1,103**（提升 18.3%）；在 Polyominoes 任务中提升 5.0%。使用开源模型（MiniMax M2.5）的实验表明，增益源于协同机制而非特定模型能力。

- **消融与机制分析**：
  - 禁用知识积累后，Kernel Engineering 性能下降 18.6%，证明知识外化的因果贡献；
  - 4 智能体协同显著优于 4 次独立单智能体运行取最优，证明增益来自协同而非单纯计算扩展；
  - 轨迹分析显示，本地验证与知识访问显著提升改进率，跨智能体信息转移贡献了 66% 的新纪录。

### 5. 结论与展望
CORAL 表明，通过增强智能体自主性与多智能体协同，可显著提升开放式发现任务的搜索效率与最终性能。论文同时指出未来方向：开发轻量化本地模型、引入异质性智能体角色、实现评估器与求解器的协同进化，以及建立更复杂的记忆架构与安全保障机制。
