# CodeScout: An Effective Recipe for Reinforcement Learning of Code Search Agents

**arXiv**: [2603.17829](https://arxiv.org/abs/2603.17829) · [PDF](https://arxiv.org/pdf/2603.17829)  
**领域**: Agent

## 摘要

> 本文提出了一种名为CodeScout的强化学习配方，用于训练代码搜索智能体。该方法的核心创新在于，仅使用标准Unix终端作为工具，通过精心设计的强化学习训练方案（包括环境改造、奖励设计和优化策略），使智能体在代码定位任务上取得了优异性能。在SWE-Bench系列基准测试中，其模型性能优于或媲美体量大2-18倍的基础及后训练大语言模型，有时甚至接近Claude Sonnet等闭源模型的水平。作者团队来自卡内基梅隆大学（CMU）等知名机构，研究背景扎实。

## 详细分析

## 问题定义
论文旨在解决**代码定位**这一核心问题，即在大规模代码仓库中，给定一个GitHub问题描述，如何准确识别出需要修改的相关文件、模块和函数。这是自动化代码代理（如修复软件缺陷）执行仓库级任务的关键前提。当前，虽然存在基于嵌入检索（如向量搜索）的方法，但近期研究转向开发能够自主导航仓库的**智能体化代码搜索代理**。然而，现有方法大多依赖于复杂、特定于编程语言（如Python）的静态分析工具（如代码图、符号解析器），这增加了部署的复杂性和工程开销。因此，本文的核心研究问题是：**能否设计一个有效的强化学习配方，训练一个仅配备标准Unix终端（Bash）的代码代理，使其在代码定位任务上达到甚至超越那些使用复杂、专用工具的代理的性能？** 论文的目标是提供一个公开、可复现的训练方法，并证明其有效性。

## 相关工作
相关工作主要分为两类：
1.  **基于嵌入检索的代码搜索**：如向量数据库方法，通过语义相似性检索相关代码片段。这类方法通常作为独立的预处理步骤。
2.  **智能体化代码搜索**：使用大型语言模型（LLM）作为代理，通过调用工具迭代式地探索代码库。现有方法（如LocAgent、RepoNavigator、CoSIL、RepoSearcher）的核心特点是**依赖语言特定的静态分析工具**（如AST解析器、调用图构建器、符号跳转工具）来增强代理的导航能力。这些方法虽然有效，但存在局限性：
    *   **语言依赖性**：工具通常针对Python设计，难以扩展到其他语言。
    *   **工程复杂性**：需要实现和维护专门的工具和脚手架。
    *   **训练数据依赖**：部分方法（如LocAgent、RepoSearcher）依赖于从闭源模型（如GPT-4）进行监督蒸馏来生成训练数据，成本高昂且受限于闭源模型。

与现有工作相比，**CodeScout** 的关键区别在于：
*   **工具极简**：代理脚手架仅使用**标准Bash终端**和一个提交预测结果的工具，使其天生与编程语言无关。
*   **训练方法**：直接使用**强化学习**对开源模型进行训练，摆脱了对闭源模型生成数据的依赖。
*   **工程简化**：工具数量少（仅1个核心工具），行动空间小，易于集成到现有通用编码代理框架中。

## 解决方案
论文提出了一套名为 **CodeScout** 的完整强化学习训练配方，核心包括四个部分：

1.  **数据与环境构建**：
    *   从SWE-Smith等数据集中提取训练实例，每个实例包含一个问题描述、问题修复前的代码仓库状态。
    *   从真实的GitHub修复补丁中，自动提取三个粒度的**真实定位目标**：修改的文件、模块和函数。
    *   环境构建简单，仅需克隆仓库，无需安装依赖或沙箱，因为定位任务不涉及代码执行。

2.  **代理脚手架（OpenHands-Bash）**：
    *   基于OpenHands SDK构建，核心工具是一个支持标准Unix命令（`ls`, `find`, `grep`, `ripgrep`等）的**终端**。
    *   引入一个**结构化输出工具**（`LocalizationFinish`），要求代理通过调用此工具来提交预测的文件、模块和函数列表，避免了早期基于字符串输出格式的解析脆弱性问题，提高了奖励信号的稳定性。

3.  **奖励设计**：
    *   核心奖励基于预测结果与真实目标在**文件、模块、函数**三个粒度上的**F1分数**之和。这鼓励代理做出精确且全面的预测。
    *   针对训练中出现的代理耗尽步数而不提交结果的问题，为较大模型（14B）引入了**辅助二元奖励**，鼓励代理在规定步数内及时终止。
    *   实验发现，鼓励并行工具调用的额外奖励会损害性能，因此改为在提示中明确建议使用并行调用。

4.  **强化学习训练算法**：
    *   使用**SkyRL**框架进行异步训练，提高GPU利用率。
    *   采用**分组序列策略优化（GSPO）** 作为核心RL算法。该算法在序列级别计算重要性采样比率和优势函数，并进行裁剪，以稳定策略更新。
    *   进行了关键调整：移除了KL散度正则化项，简化了优势计算（仅减去组内平均奖励），并对耗尽步数的轨迹屏蔽了损失。

## 实验验证
**实验设计**：
*   **训练数据**：使用39K个不重叠的Python仓库实例进行训练。
*   **评估基准**：在三个流行的SWE-Bench变体上进行评估：**Lite**、**Verified**和**Pro**，衡量文件、模块、函数级别的F1分数。
*   **基线模型**：
    *   **开源基座/指令微调模型**：如Qwen3、CodeQwen2、DeepSeek-Coder系列。
    *   **使用复杂脚手架的后训练模型**：如LocAgent、RepoNavigator、CoSIL。
    *   **闭源模型**：如Claude Sonnet、GPT-4o。
*   **训练模型**：基于Qwen3系列，训练了三个规模的CodeScout模型：1.7B、4B和14B。其中1.7B模型先用CodeScout-14B的成功轨迹进行监督微调（RFT）预热，再进行RL训练。

**主要结果**：
1.  **显著超越同规模及更大规模的基础LLM**：CodeScout-4B和-14B在几乎所有基准和粒度上都大幅超越了其对应的基础Qwen3模型以及更大的基础模型（如Qwen3-32B）。
2.  **优于使用复杂脚手架的后训练大模型**：CodeScout-14B在多数情况下性能优于或持平于使用专用工具（如图形导航、符号跳转）的更大模型（如LocAgent-32B、RepoNavigator-32B），证明了仅用Bash终端的有效性。
3.  **缩小与闭源模型的差距**：CodeScout-14B的性能有时能接近Claude Sonnet等前沿闭源模型，展示了开源方案在代码定位任务上的竞争力。
4.  **有效提升问题解决率**：分析表明，将CodeScout的定位结果作为上下文提供给问题修复代理，能显著提高SWE-Bench上的问题解决率（通过率）。
5.  **训练行为演化分析**：训练过程中，代理逐渐学会更有效地使用`ripgrep`等搜索工具，并减少冗余操作（如反复`ls`），行为更加高效。

## 未来工作
论文在附录和讨论中指出了以下局限性和未来方向：
*   **编程语言限制**：当前训练和评估主要集中于Python。虽然Bash终端本身是语言无关的，但训练数据的单一性可能限制模型对其他语言的泛化能力。未来需要扩展到多语言场景。
*   **训练稳定性**：RL训练，尤其是对于较大模型，仍可能出现训练崩溃或需要精心设计的辅助奖励（如终止奖励）。需要进一步研究更稳定、高效的RL算法和训练技巧。
*   **与问题解决的更深度集成**：目前定位和修复是两个相对分离的阶段。未来可以探索**端到端的训练**，让代理同时学习定位和修改代码，或者进行更紧密的交替式训练。
*   **处理更复杂的代码变更**：当前方法过滤掉了创建/删除文件或涉及非Python文件的问题。如何让代理处理这些情况是一个挑战。
*   **探索不同的RL算法**：附录中对比了GSPO与PPO，发现GSPO更优，但仍有空间探索其他先进的在线或离线RL算法。
*   **脚手架与工具的进一步简化与优化**：虽然已极简，但仍可研究如何通过更好的提示工程或少量关键工具进一步增强Bash终端代理的能力。

## 总结
本文的主要贡献和价值总结如下：
1.  **提出并验证了一个有效的RL训练配方**：首次公开、系统地展示了如何仅使用**标准Bash终端**作为工具，通过强化学习训练出高性能的代码定位代理（CodeScout）。
2.  **实现了简洁性与高性能的统一**：CodeScout的脚手架极其简单（语言无关、工具少、工程开销低），但其性能却**优于或媲美**那些依赖复杂、语言特定工具的更大规模模型，有时甚至接近闭源模型水平。
3.  **提供了全面的技术细节**：论文详细阐述了从数据构建、奖励设计到RL算法选择与调整的完整流程，为社区建立了一个可复现的强基线。
4.  **促进了开源生态**：论文完全开源了所有模型、代码和数据，降低了该领域的研究门槛，鼓励社区在此基础上进行迭代和创新。
5.  **证明了RL直接训练的有效性**：摆脱了对闭源模型生成数据的依赖，展示了利用RL直接优化任务特定目标（多粒度F1）来训练开源模型的可行性。

总之，这项工作为代码智能体研究提供了一个重要的范例，表明通过精心设计的强化学习，即使使用最通用的工具，也能在复杂任务上取得卓越性能，对推动更实用、更易部署的软件工程智能体具有重要意义。
