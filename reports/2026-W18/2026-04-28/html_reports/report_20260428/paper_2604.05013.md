# Scaling Coding Agents via Atomic Skills

**arXiv**: [2604.05013](https://arxiv.org/abs/2604.05013) · [PDF](https://arxiv.org/pdf/2604.05013)  
**领域**: Agent

## 摘要

> 本文提出了一种新的代码智能体扩展范式，将训练重点从复合任务优化转向原子技能掌握。作者团队来自学术界，但未明确标注具体机构。该方法通过形式化五个基础原子技能（代码定位、代码编辑、单元测试生成、问题复现和代码审查），并采用联合强化学习进行训练，显著提升了代码智能体的泛化能力。实验结果表明，该方法在多个复合编码任务上取得了显著性能提升。

## 问题定义

这篇论文试图解决当前大型语言模型（LLM）coding agents在训练范式上的核心局限性，具体包括以下关键问题：

**1. 复合任务训练导致的过拟合与泛化不足**
- 现有coding agents主要在复合基准测试（如bug-fixing、代码重构等）上进行训练，这导致模型过度拟合特定任务分布，难以泛化到未见过的软件工程任务
- 如图1和图2所示，仅在bug-fixing任务上训练无法泛化到代码重构等其他复合任务

**2. "黑盒"式优化的脆弱性**
- 直接优化高级目标（如通过测试套件）而缺乏对中间步骤的明确监督，导致策略脆弱
- 模型倾向于记忆任务特定的启发式规则，而非学习稳健的、可复用的问题解决能力

**3. 复合任务RL扩展性的实践困难**
- 真实世界软件工程任务具有无限多样性，为每个新领域定义密集奖励函数在计算上难以承受
- 在复合任务上进行联合强化学习（Joint RL）缺乏可扩展性，无法覆盖所有可能的下游应用场景

**4. 技能间的负向干扰与权衡**
- 直接在复合任务上训练时，不同能力之间存在负向干扰，难以同时提升多项技能

为解决上述问题，论文提出将训练范式从**任务级优化**转变为**原子技能掌握**，通过定义五个可组合、可独立评估的原子技能（代码定位、代码编辑、单元测试生成、问题复现、代码审查），并在这些技能上执行联合强化学习，从而实现：
- 避免技能间的负向干扰
- 提升对未见复合任务（如bug-fixing、机器学习工程、代码安全等）的泛化能力
- 建立可扩展的coding agents训练新范式

## 解决方案

论文通过提出**基于原子技能的规模化范式（Atomic Skill-based Scaling Paradigm）**来解决上述问题，具体方案包含以下四个核心组成部分：

## 1. 原子技能的定义与形式化

论文首先将复杂的软件工程工作流分解为五个**原子技能（Atomic Skills）**，作为复杂任务的"基向量"：

| 原子技能 | 定义 | 奖励函数设计 |
|---------|------|------------|
| **代码定位（Code Localization）** | 根据自然语言问题描述，识别代码库中最相关的文件集合 | 严格匹配：预测文件集合与真实修改文件集合完全一致时奖励+1，否则-1 |
| **代码编辑（Code Editing）** | 根据代码上下文和明确编辑指令生成补丁 | 执行验证：所有单元测试和回归测试通过时奖励为1，否则为0 |
| **单元测试生成（Unit-Test Generation）** | 为目标函数生成能验证正确性并暴露边缘情况的单元测试 | 双重验证：测试在原实现上通过 **且** 在所有语义变异（buggy variants）上失败时奖励为1 |
| **问题复现（Issue Reproduction）** | 构建最小可执行脚本复现报告的问题 | 对比验证：脚本在原始代码上触发失败 **且** 在补丁应用后不再失败时奖励为1 |
| **代码审查（Code Review）** | 评估Pull Request是否正确解决问题 | 二分类判断：与正确性标签一致时奖励为1，否则为0 |

这些技能遵循三项设计原则：
- **最小自包含性**：具有精确的输入/输出规范
- **独立可评估性**：可通过沙盒环境自动评估，奖励歧义最小
- **可组合性**：作为构建块可组合解决更复杂的复合任务

## 2. 统一接口与联合强化学习框架

**统一任务接口**：所有原子技能共享相同的智能体接口，任务实例定义为三元组 $\tau = (k, x, c)$，其中 $k$ 为技能类型，$x$ 为输入，$c$ 为执行上下文。策略 $\pi_\theta(y|x)$ 将输入映射到结构化输出 $y$。

**联合RL优化**：不同于单独优化每个技能，论文提出在统一技能缓冲区上执行联合RL：

$$\max_\theta \mathbb{E}_{k\sim p(k), x\sim \mathcal{D}_k, y\sim \pi_\theta(\cdot|x)} [r_k(x, y)]$$

关键机制包括：
- **统一轨迹采样**：从混合所有技能实例的统一缓冲区中采样，不区分技能类型存储轨迹
- **共享策略参数**：所有技能共享同一策略网络，无技能特定的头部或优化器
- **GRPO（Group-based Relative Policy Optimization）**：对每个输入 $x$ 生成 $N$ 个候选输出，组内奖励归一化计算相对优势：
  $$A_i = r_i - \frac{1}{N}\sum_{j=1}^N r_j$$

这种联合训练鼓励代码理解、执行推理和工具使用的共享表征浮现，避免技能间的负向干扰。

## 3. 基础设施优化

为支撑大规模agentic RL，论文优化了三个关键基础设施组件：

**沙盒执行环境**：
- 基于Kubernetes的隔离环境，支持10,000+并发沙盒
- 瞬时生命周期（按需创建、用后销毁）防止状态泄漏
- 安全防护：禁用网络访问、移除.git历史以防止奖励黑客（reward hacking）
- Sidecar容器架构支持25,000+预构建Docker镜像，适应多样化测试环境

**最小工具脚手架**：
- 限制动作空间为确定性工具集：`bash`（命令执行）和 `str_replace`（文件编辑）
- 简化动作空间复杂度，避免脆弱或重叠的工具抽象
- 跨技能一致的工具接口促进参数共享和正向迁移

**解耦的Rollout与训练工作器**：
- Rollout工作器异步采样任务并在沙盒中执行轨迹
- Trainer工作器使用GRPO进行批量策略更新
- 解耦设计允许不同执行成本的异构技能在同一管道中高效共存，避免阻塞

## 4. 训练流程

完整训练流程分为两个阶段：
1. **监督微调（SFT）初始化**：在1,500个经过验证的轨迹（每个技能300个）上执行轻量级SFT，初始化原子技能能力，**不包括复合任务**
2. **联合RL训练**：在SFT基础上，通过上述联合RL框架在五个原子技能上持续训练

## 解决方案的核心优势

通过该范式，论文实现了：
- **无负向干扰**：联合RL同时提升所有原子技能，无技能间权衡（如图4所示，所有技能曲线单调上升）
- **组合泛化**：原子技能的改进有效泛化到未见的复合任务（如SWE-bench、Terminal-Bench等），平均性能提升18.7%
- **可扩展性**：相比为每个新复合任务设计奖励函数，原子技能提供了通用的规模化路径

实验表明，相比仅在单一复合任务（如bug-fixing）上训练，联合原子技能RL在保持域内性能的同时，显著提升了跨领域通用能力。

## 实验验证

论文进行了系统性的实验验证，涵盖**主性能评估**、**训练动态分析**、**消融对比实验**和**基础设施验证**四个维度。以下是详细实验内容：

## 1. 实验设置与评估协议

### 模型与训练配置
- **基础模型**：GLM-4.5-Air-Base（106B总参数，12B活跃参数）
- **训练流程**：
  - **Stage 1 (SFT)**：在1,500条经GPT-oss-120b生成、人工验证的轨迹上监督微调（每个技能300条），**排除所有复合任务数据**
  - **Stage 2 (Joint RL)**：使用GRPO算法在五个原子技能上进行联合强化学习
- **评估指标**：Avg@3（三次独立运行的平均性能）、Pass@1、平均环境交互步数

### 评估任务体系
| 类别 | 任务 | 说明 |
|------|------|------|
| **IID原子技能** | Code Localization | 定位需修改的文件集合 |
| | Code Editing | 根据指令生成代码补丁 |
| | Issue Reproduction | 创建脚本复现报告问题 |
| | Unit Test Generation | 为函数生成故障检测测试 |
| | Code Review | 判断PR是否正确修复问题 |
| **OOD复合任务** | SWE-bench Verified | Python真实bug修复 |
| | SWE-bench Multilingual | 跨语言bug修复 |
| | Terminal-Bench 2.0 | 终端命令行任务 |
| | Code Refactoring | 代码重构（自建300任务） |
| | SEC-bench | 安全漏洞复现与PoC生成 |

## 2. 主性能实验（表1、表2）

对比三个模型变体：
- **GLM-4.5-Air**：公开可用的思考模型（强基线）
- **Base-SFT**：仅经原子技能SFT初始化
- **Base-SFT-RL**：SFT + 联合RL训练

### 关键结果
- **原子技能提升**：联合RL相比SFT基线全面提升，Code Editing提升最显著（0.458→0.611，+33.4%），平均提升18.7%
- **OOD泛化**：在未训练的复合任务上 consistently 提升，SWE-bench Verified提升15.4%（0.507→0.585），Multilingual提升29.7%（0.300→0.389）
- **整体优势**：Joint RL模型在10个任务中的平均性能（0.452）超越SFT（0.383）和GLM-4.5-Air（0.416）

## 3. 训练动态分析（图4、表3）

### 学习曲线监测
在100个RL迭代周期中监测性能演变：
- **单调提升**：所有五个原子技能性能随训练持续上升，无坍塌或震荡
- **正迁移现象**：原子技能平均得分稳步增长（0.517→0.604），证明技能间无负向干扰
- **泛化同步性**：OOD复合任务性能与原子技能提升同步增长，验证"原子技能改进→复合任务泛化"的假设

### 详细数据（附录表3）
提供从SFT到RL-iter-100的完整检查点数据，显示：
- Avg(IID)从0.517提升至0.604

## 4. 消融实验：联合RL vs 单任务RL（图5、附录表4-5）

为验证"联合训练优于单独优化"，设计两组对照：

### 实验设置
- **Editing-Only RL**：仅在Code Editing技能上训练（代表单原子技能优化）
- **Verified-Only RL**：仅在SWE-bench Verified上训练（代表单复合任务优化）
- **Skills-Joint RL**：五个原子技能联合训练（本文方法）

### 核心发现
- **专业化局限**：Verified-Only RL虽在SWE-bench Verified上达到与联合RL相当的最终性能（0.555 vs 0.585），但在其他原子技能（如Issue Reproduction、Code Review）和OOD任务（如Refactoring）上表现明显较弱
- **广度优势**：Skills-Joint RL在所有原子技能和OOD基准上均实现更均衡、更广泛的性能提升，证明其学习的是可复用的基础能力而非任务特定启发式

## 5. 训练行为分析（图6）

分析联合RL过程中**性能与工具使用步数**的关系：
- **Code Localization/Editing/Unit Test**：性能与步数同步增加，表明模型学会更深入的代码探索和工具交互
- **Issue Reproduction**：步数与性能波动较大，反映执行环境敏感性和评估噪声
- **Code Review**：步数呈现"增加-减少-增加"的非单调模式，暗示训练早期探索、中期效率优化、晚期精细审查的策略演变

## 6. 数据去污验证（附录C.1）

实施严格的数据隔离以确保泛化真实性：
- 收集所有5个复合基准测试集的仓库URL和Commit ID
- 在SFT和RL训练前，从完整语料中移除所有相关GitHub仓库、Issue和PR
- 确保评估时模型从未见过测试代码库，验证性能提升源于能力泛化而非记忆

## 7. 基础设施压力测试

- **并发规模**：验证支持10,000+并发沙盒执行
- **奖励完整性**：验证禁用网络和.git访问有效防止奖励黑客（reward hacking）
- **异构任务处理**：验证不同执行成本的技能（轻量级单元测试 vs 重量级环境复现）可在统一管道中无阻塞共存

## 未来工作

基于论文提出的原子技能范式，以下几个方向值得进一步探索：

## 1. 原子技能库的扩展与层次化

**技能维度扩展**
当前工作定义了五个基础技能，但软件工程工作流包含更多可原子化的能力，例如：
- **依赖分析**：自动识别代码变更对上下游模块的影响范围
- **文档生成**：基于代码变更自动更新技术文档和API文档
- **性能剖析**：识别性能瓶颈并提出优化建议
- **安全审计**：静态分析潜在的安全漏洞

**层次化技能体系**
探索原子技能之间的层次关系，建立**元技能（meta-skills）**概念：
- 低层：语法级操作（如代码补全、变量重命名）
- 中层：语义级操作（当前五个技能）
- 高层：工作流级协调（如敏捷开发流程管理、代码评审流程 orchestration）

## 2. 动态技能组合机制

**显式技能编排**
当前采用隐式联合训练，未来可研究**显式技能组合**：
- 开发技能编排语言，允许模型根据任务需求动态组合原子技能（如"先定位→再复现→最后编辑"的显式规划）
- 引入技能依赖图（Skill Dependency Graph），建模技能间的因果依赖关系

**自适应技能选择**
研究基于上下文的动态技能路由机制：
$$p(k|x) = \text{Router}_\phi(x)$$
其中路由器网络根据输入任务自动选择激活哪些原子技能，避免无关技能的计算开销。

## 3. 跨领域泛化与迁移

**其他领域的原子技能**
验证"原子技能→复合任务"的范式是否适用于其他需要工具使用的领域：
- **科学研究**：文献检索、实验设计、数据分析、论文撰写作为原子技能
- **商业分析**：数据清洗、可视化、趋势预测、报告生成
- **创意写作**：角色设计、情节构建、文风适配、事实核查

**跨语言代码能力**
当前多语言支持有限，可扩展原子技能到更多编程语言范式（函数式、逻辑式、并发语言），研究技能在不同语言间的迁移性。

## 4. 理论分析与可解释性

**组合泛化的理论保证**
从表示学习角度分析：

**执行效率感知**
在奖励中引入计算成本考量：
$$r_{\text{efficiency}} = r_{\text{correctness}} - \lambda \cdot \text{ExecutionTime}$$
鼓励模型不仅正确完成任务，而且以更高效的方式（更少的工具调用步骤、更低的计算资源消耗）完成。

## 1. 问题识别
当前LLM编码智能体主要在**复合基准任务**（如bug修复、代码重构）上训练，导致：
- **任务特定过拟合**：优化高级目标（如通过测试套件）缺乏中间步骤监督，模型倾向于记忆启发式规则而非学习稳健的问题解决能力
- **泛化能力受限**：在某一复合任务（如bug修复）上训练无法泛化到其他任务（如代码重构）
- **扩展性瓶颈**：真实世界软件工程任务无限多样，为每个领域设计密集奖励函数计算上不可行

## 2. 核心方法：原子技能范式
论文将复杂软件工程工作流分解为五个**最小自包含、可独立评估、可组合**的原子技能：

- **代码定位（Code Localization）**：识别与问题相关的文件集合
- **代码编辑（Code Editing）**：根据指令生成正确补丁
- **单元测试生成（Unit-Test Generation）**：生成能检测语义错误的测试用例
- **问题复现（Issue Reproduction）**：构建脚本复现报告的问题
- **代码审查（Code Review）**：判断代码变更是否正确解决问题

每个技能配备基于沙盒执行的精确奖励函数，遵循统一接口 $\tau=(k, x, c)$。

## 3. 联合强化学习框架
提出**跨技能联合RL**（Joint RL）：
- **统一策略**：单一共享策略 $\pi_\theta$ 处理所有技能，无特定任务头
- **混合采样**：从统一技能缓冲区采样，使用GRPO（Group-based Relative Policy Optimization）优化，通过组内奖励归一化缓解跨技能奖励尺度差异
- **基础设施**：Kubernetes-based沙盒支持10,000+并发执行，最小工具集（bash + str_replace）确保动作空间一致性

## 4. 实验验证
在GLM-4.5-Air-Base（106B参数）上进行两阶段训练（SFT初始化 → Joint RL）：

**关键结果**：
- **原子技能提升**：相比SFT基线，联合RL使5个原子技能平均提升18.7%（如Code Editing从0.458→0.611）
- **OOD泛化**：在未训练的5个复合基准（SWE-bench Verified/Multilingual、Terminal-Bench、代码重构、安全基准）上均实现一致提升，SWE-bench Verified提升15.4%
- **对比优势**：与单任务RL（仅训练bug修复或仅训练代码编辑）相比，联合RL在保持域内性能的同时，显著提升了跨领域通用能力，避免了技能间的负向干扰

通过将训练焦点从**任务级优化**转向**原子技能掌握**，论文证明了：
- 原子技能是复杂软件工程任务的"基向量"，其改进可组合泛化到未见复合任务
