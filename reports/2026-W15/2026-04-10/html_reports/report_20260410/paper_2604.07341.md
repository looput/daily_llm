# ReCodeAgent: A Multi-Agent Workflow for Language-agnostic Translation and Validation of Large-scale Repositories

**arXiv**: [2604.07341](https://arxiv.org/abs/2604.07341) · [PDF](https://arxiv.org/pdf/2604.07341)  
**领域**: Agent  
**作者**: Ibrahimzada, Paulsen, Kroening, Jabbarvand  
**综合评分**: 7.74  （novelty: 9.0 · method: 8.5 · evidence: 8.5 · clarity: 8.0）

## 摘要

> 本文提出了一种名为ReCodeAgent的自主多智能体方法，用于实现语言无关的仓库级代码翻译与验证。该方法首次实现了跨多种编程语言的高翻译成功率，在118个真实世界项目上验证了其有效性，覆盖6种编程语言和4种语言对。实验结果表明，ReCodeAgent在翻译正确性上持续优于现有技术，将测试通过率提高了60.8%。

## 问题定义

这篇论文试图解决**仓库级代码翻译与验证中的语言可扩展性瓶颈**问题。具体而言，论文针对以下核心挑战：

### 1. 单一语言对的工程局限
现有技术（基于规则或神经符号方法）通常针对**单一源-目标编程语言对**（如仅 C→Rust 或仅 Java→Python）进行设计和评估。支持新语言对需要巨大的工程投入（规则类工具超 10 万行代码，神经符号类工具超 1 万行代码），难以扩展到二次方增长的跨语言翻译需求。

### 2. 缺乏真正语言无关的自动化方案
现有智能体（Agent）方法存在以下局限：
- **工具依赖**：要么仅使用基础探索工具，要么依赖特定语言的专用工具（如 CodeQL），无法通用化；
- **幻觉问题**：在长程的仓库级翻译任务中，智能体容易产生关于类/文件/方法名、库匹配或测试断言的幻觉，导致代码无法编译或功能不一致；
- **测试翻译困境**：简单地将"翻译"与"验证"分离会导致测试质量下降（如删除断言），而现有方法未有效处理测试翻译与代码翻译的耦合关系。

### 3. 评估透明性与过程缺失
现有研究缺乏对智能体架构设计选择的系统性分析，也未充分讨论测试翻译的局限性（如断言删除、低质量生成测试导致的假阳性），且缺少对成本与执行轨迹的透明报告。

### 解决方案概述
为此，论文提出 **ReCodeAgent**——一种**多智能体、语言无关**的仓库级代码翻译与验证框架。通过将任务分解为**分析（Analyzer）→规划（Planning）→翻译（Translator）→验证（Validator）**四个阶段，并利用模型上下文协议（MCP）工具实现跨语言的静态分析，ReCodeAgent 能够在无需针对特定语言编写复杂工程代码的前提下，自动完成多语言对（涵盖 C、Go、Java、JavaScript、Python、Rust 等）的高质量代码迁移与验证。

## 解决方案

论文通过提出 **ReCodeAgent** 框架，采用**多智能体协作架构**与**语言无关的工具链**，系统性地解决了仓库级代码翻译的可扩展性与自动化难题。具体解决方案包括以下五个层面：

### 1. 多阶段智能体分工（解决复杂工程依赖）
将传统单一工具或单智能体的复杂工程任务，分解为四个专业化的智能体，每个智能体负责特定阶段：

- **Analyzer Agent（分析智能体）**：通过 **Model Context Protocol (MCP)** 工具对源项目进行静态分析，生成项目结构报告、第三方库映射分析及目标语言设计文档，替代了传统神经符号方法中依赖 CodeQL 等特定语言的分析组件。
- **Planning Agent（规划智能体）**：基于分析结果提取翻译单元（函数/类/方法），建立名称映射表（确保命名一致性），生成项目骨架（Skeleton）文件，并制定依赖感知的实现计划（Part A翻译源码，Part B翻译测试），从源头避免长程任务中的幻觉问题。
- **Translator Agent（翻译智能体）**：按规划执行代码与测试的协同翻译（Co-translation），在收到验证报告后进入修复模式（Repair Mode）。
- **Validator Agent（验证智能体）**：独立执行测试验证与覆盖缺口分析，对未覆盖函数生成额外测试，形成"翻译-验证-修复"的闭环。

### 2. 语言无关的工具链（实现PL-Agnosticism）
通过 **MCP（Model Context Protocol）** 封装两类通用工具，消除对特定语言分析引擎的依赖：

- **Language Server Protocol (LSP) 工具**：利用六种语言（C、Go、Java、JavaScript、Python、Rust）的LSP服务器，提供跨语言的语义级操作（定义跳转、诊断、悬停提示、引用查找、符号重命名等）。新增语言支持仅需安装对应的LSP服务器，无需编写额外代码。
- **Project Analysis (PA) 工具**：基于 Tree-sitter 等轻量级解析器，提供目录结构提取（`get_directory_tree`）与文件结构解析（`get_file_structure`），帮助智能体快速理解代码库而无需逐文件读取，显著降低Token消耗。

### 3. 结构化规划与骨架生成（抑制幻觉）
针对长程任务中的幻觉问题（如错误的方法名、文件结构），ReCodeAgent 采用：
- **严格的一对一结构映射**：在规划阶段强制要求源项目与目标项目在目录结构、文件组织、标识符命名上保持一致。
- **骨架先行（Skeleton-First）**：先生成包含类声明和方法签名但无具体实现的骨架文件，确保架构正确后再填充实现，避免因结构错误导致的连锁幻觉。
- **名称映射表（Name Mapping）**：显式维护源语言到目标语言的符号映射（如 `go.NewLuhn` → `rs.NewLuhn`），防止LLM随意重命名导致的功能不一致。

### 4. 测试翻译与验证分离（解决测试翻译困境）
针对"翻译与验证目标冲突"及"测试翻译耦合"问题：
- **协同翻译（Co-translation）**：Translator Agent 同时翻译源码和测试代码，确保测试对源码的语义依赖被正确保留。
- **独立验证**：Validator Agent 独立执行测试，避免翻译智能体为通过测试而篡改断言（如删除或放宽验证条件）。
- **覆盖引导的测试生成**：当现有测试覆盖率不足（如 AlphaTrans 基准中部分项目仅38.7%覆盖率）时，Validator Agent 自动为未覆盖函数生成新测试，并在源语言和目标语言中执行比对，确保行为一致性。

### 5. 透明化评估与成本控制（过程中心分析）
论文通过过程中心指标（Process-centric Metrics）验证设计选择的有效性：
- **轨迹分析**：使用 GraphEctory 工具分析智能体执行轨迹的节点数、时序边数、循环长度等，证明多智能体架构相比单智能体基线（Base Agent）减少了28%的无效率探索。
- **成本可控**：平均每个项目翻译成本为 **$15.3**，耗时 **57分钟**，且成本与代码规模呈线性关系，远低于传统方法所需的数万行语言特定代码维护成本。

通过这种"分析-规划-翻译-验证"的流水线，ReCodeAgent 无需为每种语言对编写特定规则（如 C2Rust 的10万行代码），即可支持六种编程语言间的跨语言翻译，实现了真正的**语言无关自动化**。

## 实验验证

论文在第4节（Evaluation）中系统性地设计了四类实验，以验证 ReCodeAgent 的有效性、测试翻译质量、组件贡献及经济可行性。以下是详细说明：

## 1. 实验设置（§4.1）

**基准测试（Benchmark）**：选取4个现有技术的公开基准，共 **118个真实项目**，总计超过 **230K行代码（LoC）**，涵盖：
- **6种编程语言**：C, Go, Java, JavaScript, Python, Rust
- **4个语言对**：C→Rust（Crust）、Go→Rust（Oxidizer）、Java→Python（AlphaTrans）、Python→JavaScript（Skel）

**对比技术（Competing Techniques）**：
- **Skel** [80]：Python→JavaScript 神经符号方法
- **Oxidizer** [99]：Go→Rust 类型驱动翻译
- **AlphaTrans** [26]：Java→Python 组合式神经符号方法
- **SWE-agent** [92]：C→Rust 智能体方法（Crust基准）

**大语言模型**：使用 **Anthropic Claude 4.5 Sonnet** 作为后端模型。

## 2. RQ1：有效性实验（§4.2）

从三个维度评估翻译质量：

### (1) 语法正确性（Syntactic Correctness）
- **指标**：编译成功率（Compilation Success, CS）
- **结果**：ReCodeAgent 达到 **99.4%**，对比方法为 **96.9%**。在 C→Rust 的 Crust 基准上提升最显著（SWE-agent 仅 40% 编译成功，ReCodeAgent 达 89%）。

### (2) 测试验证（Test Validation）
- **验证过的开发者测试（Validated Developer Tests）**：使用人工验证的测试套件避免测试翻译错误带来的偏差。ReCodeAgent 测试通过率为 **86.5%**（1,822/2,107），比对比方法（25.7%）**提升 60.8%**。
- **ReCodeAgent 翻译的测试**：在 1,484 个翻译测试中，**98.1%** 通过（28个失败）。
- **生成测试（Generated Tests）**：针对覆盖率不足的项目，Validator Agent 生成 3,642 个额外测试，通过率达 **99.6%**（13个失败），将平均代码覆盖率从 **70.8% 提升至 85.4%**。

### (3) 函数验证（Function Validation）
为避免测试耦合效应（Test Coupling Effect），独立验证每个函数：
- **结果**：ReCodeAgent 验证成功率为 **97.8%**（1,366/1,397），对比方法仅 **66.9%**（935/1,397），提升 **30.9%**。

## 3. RQ2：测试翻译质量分析（§4.3）

评估 ReCodeAgent 翻译的 1,484 个开发者测试与原始测试的语义等价性：

| 评估指标 | 结果 |
|---------|------|
| **翻译完整性** | 100%（1,484/1,484）成功翻译，无空逻辑测试 |
| **断言数量匹配** | 99.3%（1,473/1,484）保持相同断言数量 |
| **AssertEqual 输出匹配** | 100%（1,891/1,891）预期输出值等价 |
| **断言类型匹配** | AssertEqual: 98.54%，AssertTrue: 95.20%，AssertFalse: 90.54% |
| **语义相似度** | 平均余弦相似度 **0.91**（基于 Qwen Embedding） |
| **代码结构** | 行数差异 <1%，方法调用减少 7%（符合目标语言惯用法） |

## 4. RQ3：消融实验（§4.4）

通过逐步移除组件验证各智能体的贡献：

- **No Analyzer (NoA)**：移除分析智能体，测试通过率 **下降 22.7%**，轨迹节点数增加（探索效率降低）。
- **No Planning (NoP)**：移除规划智能体，测试通过率 **下降 25.3%**，智能体缺乏结构化指导导致重复尝试。
- **No Validator (NoV)**：移除验证智能体，测试通过率 **下降 30.3%**，翻译错误累积且无反馈修复。
- **Base Agent (BA-α/BA-β)**：单智能体基线（紧凑提示 vs 全提示连接），通过率分别仅为 **25.3%** 和 **24.1%**，比 ReCodeAgent **低 61.2% 和 62.4%**。

**过程中心分析（Process-centric Analysis）**：
使用 GraphEctory 工具分析执行轨迹，发现：
- 多智能体架构使轨迹节点数（NC）和时序边数（TEC）**降低 28%**；
- 单智能体基线存在大量无效循环探索，而 ReCodeAgent 轨迹更紧凑高效。

## 5. RQ4：成本与工具使用分析（§4.5）

### 经济成本
- **平均成本**：**$15.3/项目**，耗时 **57分钟/项目**；
- **规模敏感性**：
  - AlphaTrans（大型项目）：$76，258分钟
  - Crust（小型项目）：$11，45分钟
- 成本与代码规模呈线性关系，远低于传统方法（需 3,843–19,052 LoC 的语言特定实现）。

### 工具使用分布
- **高频核心工具**：`Read`（~15K次）、`Bash`（~15K次）、`Edit`（~15K次）；
- **LSP语义工具**：`file_structure`（~1,000次）、`hover`（~150次）、`definition`（~40次），证明智能体主要依赖语义理解而非简单文本匹配。

这些实验共同验证了 ReCodeAgent 在无需语言特定工程投入的前提下，实现了比现有技术更高的翻译正确率和更低的执行成本。

## 未来工作

基于论文内容，可以从以下几个维度识别出值得进一步探索的研究方向：

## 1. 扩展语言覆盖与复杂性
- **更多语言对的验证**：论文验证了6种语言（C, Go, Java, JavaScript, Python, Rust），但**语言无关性**在更具差异性的语言对（如函数式语言 Haskell/Scala、面向对象与函数式混合范式、或具有复杂类型系统的语言如 TypeScript 的高级泛型）上仍需验证。
- **复杂语言特性的处理**：当前方法在处理 C++ 模板元编程、Rust 的复杂生命周期约束、或异步编程模式（async/await 跨语言映射）时的有效性有待深入研究。

## 2. 形式化验证与安全性保证
- **超越测试的验证**：当前主要依赖测试执行进行验证，存在假阳性风险。可探索结合**形式化验证工具**（如 Rust 的 Miri 检查未定义行为、C 的内存安全证明、或语义等价性验证器）来提供更强的正确性保证，特别是对于不安全代码块（unsafe blocks）的翻译。

## 3. 超大规模项目的可扩展性
- **工业级代码库**：论文评估的项目平均约 2K LoC，最大约 37K LoC。需要验证在**百万行级工业仓库**上的表现，包括：
  - 长程依赖分析的准确性
  - 成本可接受性（当前大型项目已达 $76，超大规模可能成本过高）
  - 分模块增量翻译的策略优化

## 4. 智能体架构的动态优化
- **自适应协作机制**：当前采用固定的四阶段流水线（Analyzer → Planning → Translator → Validator）。可探索**动态智能体协作**，例如根据项目特性自动调整阶段顺序、智能体数量，或引入对抗性验证智能体（Adversarial Validator）进一步检测边界情况。
- **强化学习优化**：利用历史翻译轨迹训练策略模型，优化规划阶段的依赖分析顺序和测试生成策略，减少试错成本。

## 5. 翻译质量的多维评估
- **语义保持的细粒度度量**：当前主要依赖功能测试通过率，可引入**代码语义嵌入相似度**（除论文已用的 cosine similarity 外）、API 使用模式对比、或人工专家评估翻译代码的**地道性（Idiomaticity）**。
- **长期可维护性**：评估翻译后代码在实际维护场景中的可读性、开发者接受度，以及后续迭代开发的难易程度。

## 6. 稳健性与确定性
- **非确定性控制**：论文指出因 LLM 的随机性，每个实验仅运行一次。未来需研究**多次运行的方差控制**、一致性保障机制，以及确定性重放（deterministic replay）技术。
- **数据污染评估**：论文提及基准项目可能包含在训练数据中，需在新收集的、确保未见过的大型真实项目上验证性能。

## 7. 测试生成的智能化
- **高质量断言生成**：当前生成测试的通过率为 99.6%，但可进一步探索**基于规约的测试生成**（如利用符号执行生成更高覆盖率的边界条件测试），或结合被测代码的动态行为学习生成更具针对性的断言。

## 8. 成本与效率优化
- **分层翻译策略**：对于超大型项目，可探索**粗粒度到细粒度的分层翻译**（先翻译接口/骨架，再按需翻译实现），或利用缓存机制避免重复分析未变更的依赖模块，以降低 Token 消耗和执行时间。

## 总结

这篇论文提出了 **ReCodeAgent**，一种面向大规模代码仓库的多智能体自动化翻译与验证框架，旨在解决现有技术过度依赖特定编程语言、工程成本高昂的问题。以下是核心内容的系统总结：

### 1. 研究背景与问题
仓库级代码翻译（将完整代码库从一种语言迁移至另一种语言）对软件现代化至关重要，但现有方案存在显著局限：
- **语言特异性**：规则型（如 C2Rust）和神经符号型工具（如 AlphaTrans）需为每对语言编写数万行专用代码，难以扩展到多语言场景；
- **智能体缺陷**：现有智能体方法或依赖单一语言工具（如 CodeQL），或缺乏对长程任务中幻觉（hallucination）的控制，且未妥善处理测试翻译与验证的目标冲突；
- **评估盲区**：缺乏对架构设计选择的系统性分析，以及过程中心（process-centric）的轨迹评估。

### 2. 技术方案
ReCodeAgent 采用**四阶段多智能体架构**，通过任务分解与语言无关工具链实现自动化：

- **Analyzer Agent**：利用 **Model Context Protocol (MCP)** 与 **Language Server Protocol (LSP)** 工具进行跨语言静态分析，生成项目结构报告、第三方库映射及目标语言设计文档，替代传统特定语言的分析引擎；
- **Planning Agent**：提取翻译单元（函数/类），建立严格名称映射，生成项目骨架（Skeleton）及依赖感知的实现计划（源码翻译与测试翻译分离为 Part A 与 Part B）；
- **Translator Agent**：执行协同翻译（同时翻译源码与测试），并在验证失败时进入修复模式；
- **Validator Agent**：独立执行测试验证，进行覆盖缺口分析，并为未覆盖函数生成额外测试，形成"翻译-验证-修复"闭环。

### 3. 关键创新
- **语言无关性**：通过统一封装 LSP 工具（支持 C、Go、Java、JavaScript、Python、Rust 等），新增语言仅需安装对应语言服务器，无需编写额外代码；
- **幻觉抑制**：骨架先行（Skeleton-First）策略与严格一对一结构映射，确保目录、文件名、标识符命名的一致性；
- **测试处理**：分离测试翻译与验证职责，避免智能体为通过测试而篡改断言，同时通过覆盖引导的测试生成解决原始测试覆盖不足问题（平均覆盖率从 70.8% 提升至 85.4%）。

### 4. 实验评估
在 **118 个真实项目**（总计 230K+ LoC，涵盖 C→Rust、Go→Rust、Java→Python、Python→JavaScript 四个语言对）上的评估表明：

| 指标 | ReCodeAgent | 现有技术 | 提升 |
|------|-------------|----------|------|
| 编译成功率 | **99.4%** | 96.9% | 2.5% |
| 测试通过率 | **86.5%** | 25.7% | **60.8%** |
| 函数验证成功率 | **97.8%** | 66.9% | 30.9% |
| 平均成本 | **$15.3/项目** | - | 经济性显著 |

**消融实验**证实多智能体架构的必要性：移除 Analyzer、Planning 或 Validator 任一组件，测试通过率分别下降 22.7%、25.3% 和 30.3%；而单智能体基线性能下降超过 60%。

### 5. 贡献与影响
- **技术贡献**：首个无需语言特定工程投入的多智能体仓库级翻译管道；
- **实证贡献**：在六种编程语言、四个语言对上验证有效性，证明其显著优于现有神经符号与智能体方法；
- **开源工具**：实现代码与实验轨迹已公开，支持可重复研究。

ReCodeAgent 展示了通过 LLM 智能体与通用静态分析工具结合，实现可扩展、经济高效的跨语言软件迁移的可行性，为遗留系统现代化提供了实用解决方案。
