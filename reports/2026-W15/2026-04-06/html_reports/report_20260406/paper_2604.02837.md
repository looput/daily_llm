## 摘要

> 本文首次对新兴的Agent Skills开放标准进行了全面的安全分析。研究系统性地定义了Agent Skill的完整生命周期（创建、分发、部署、执行），并基于此构建了一个包含七类十七种场景的威胁分类法，覆盖三个攻击层面。研究通过分析五个已确认的安全事件验证了分类法的有效性，并针对性地提出了防御方向、开放挑战和行动建议。论文揭示了框架本身的结构性缺陷是主要威胁来源，具有重要的警示和实践价值。

## 问题定义

这篇论文试图解决**Agent Skills框架的系统性安全问题**。具体而言，论文针对以下核心问题展开研究：

## 核心问题识别

**Agent Skills作为新兴的LLM智能体能力扩展标准，在缺乏充分安全机制的情况下被快速广泛采用，导致其暴露于严重的结构性安全威胁之中。**

论文指出，尽管Agent Skills已被多个主流平台（如Claude、Cursor、GitHub Copilot、Gemini CLI）采用，并形成了大规模的社区市场，但以下结构性缺陷构成了严峻的安全挑战：

1. **架构层面的安全边界缺失**：自然语言指令与可执行代码在文件系统包中混合（缺乏数据-指令边界），导致提示注入攻击难以防御
2. **信任模型的结构性缺陷**：单次安装批准即授予持久化的操作员级权限，存在严重的**同意差距（consent gap）**
3. **分发治理的真空**：开放市场缺乏强制性安全审查，使得供应链攻击（如 typosquatting、仓库劫持）易于实施

## 研究目标

论文旨在通过以下方式解决上述问题：

- **建立系统性的威胁分类体系**：识别跨越创建、分发、部署、执行四个生命周期的**7大威胁类别**和**17种具体攻击场景**
- **验证真实世界影响**：分析已确认的5起重大安全事件（包括MedusaLocker勒索软件攻击、ClawHavoc供应链攻击等），证明威胁并非理论假设
- **提出防御研究方向**：针对每类威胁讨论缓解策略，并识别**5个开放研究挑战**（如自然语言指令分析、同意模型设计、多智能体信任传播等）
- **提供可操作的治理建议**：为技能作者、市场运营商、平台开发者和企业用户分别提出具体的安全实践指导

论文的核心论点是：Agent Skills最严重的威胁源于框架本身的结构属性，无法通过简单的增量式缓解措施解决，而需要进行架构层面的改革。

## 相关工作

根据论文第8节（Related Work），相关研究主要涵盖以下四个领域：

## 1. LLM 对抗鲁棒性（LLM Adversarial Robustness）
该领域研究语言模型对对抗性输入的脆弱性，主要包括：
- **越狱攻击（Jailbreaks）**：诱导模型输出违反政策的内容
- **提示注入攻击（Prompt Injection）**：通过对抗性指令劫持模型行为
- **模型提取与成员推断攻击**：针对模型权重的攻击

**研究局限**：现有工作将**模型本身**作为主要攻击面，关注输入扰动或训练数据攻击。而 Agent Skills 的威胁源于**扩展机制**（信任建立、权限范围、供应链妥协），而非模型本身，因此现有技术对 Agent Skills 场景的迁移性有限。

## 2. 扩展生态系统安全（Extension Ecosystem Security）
研究浏览器扩展和 IDE 插件的安全问题，与 Agent Skills 具有相似的社区贡献、动态加载和广泛权限特征：
- **Chrome 扩展**：大规模恶意与过度授权扩展群体研究
- **VS Code 扩展**：广泛的可疑行为模式研究
- **插件审查流程**：基于人工审查的 vetting 在大规模下的系统性局限

**关键差异**：Agent Skills 增加了**自然语言指令交付**维度。与基于代码的扩展可通过静态分析检测 API 调用和权限使用不同，Skill 的行为规范以自然语言书写，由语言模型动态解释，使得对完整行为范围的静态分析从根本上更加困难。

## 3. 软件供应链安全（Software Supply Chain Security）
针对包仓库妥协攻击的研究，包括：
- **重大事件**：SolarWinds、XZ Utils 等
- **检测技术**：恶意包检测、依赖混淆（Dependency Confusion）防御
- **来源验证**：加密来源验证框架（如 in-toto、sigstore）

**Agent Skills 的特殊性**：
- 恶意负载交付**无需**编译二进制文件或注入可执行代码
- 单个 SKILL.md 文件中的**一句对抗性指令**即可在操作员权限级别重定向智能体行为
- 与二进制供应链攻击可通过加密完整性检查检测不同，恶意 SKILL.md 的行为效应在没有预期行为基准规范的情况下，无法与良性指令漂移区分

## 4. 基于 LLM 的智能体安全（LLM-based Agent Security）
专门针对 LLM 智能体安全威胁的研究：

### 综述性工作
- **Gan et al.**：涵盖威胁源和影响的综合分类
- **He et al.**：代表性部署中的安全与隐私问题案例研究
- **Yu et al.**：多智能体信任动态研究
- **Datta et al.**：评估方法与开放挑战的广泛论述

### 具体攻击向量研究
- **提示注入**：
  - *Greshake et al.*：提出**间接提示注入**（Indirect Prompt Injection），证明外部内容中的对抗性指令可劫持智能体行为
  - 后续工作：攻击分类形式化、基准测试（如 InjecAgent、AgentDojo）、自适应攻击下的防御难度分析

- **防御方法**：
  - *Chen et al.*：StruQ（结构化查询格式）
  - *Wallace et al.*：基于特权的指令层次结构（Instruction Hierarchy）
  - **局限性**：这些防御依赖于操作层与用户层之间的特权边界，在 Agent Skills 中架构不适用——恶意 SKILL.md 设计即在操作层运行，且与合法 Skill 内容结构不可区分

- **其他攻击**：
  - *Chen et al.*：AgentPoison，针对基于 RAG 的智能体，通过污染长期记忆实施攻击
  - *Yang et al.*：智能体后门攻击的形式化，可通过数据投毒或权重操纵嵌入

### 最接近的相关工作
**Hou et al. 的 MCP 安全分析**：识别了 MCP 生命周期中的九大威胁类别。然而，Agent Skills 引入了 MCP 不具备的架构属性：
- 自然语言指令载体（替代类型化接口）
- 缺乏类型接口契约
- **单次批准持久信任模型**（Single-approval Persistent Trust Model）

**研究缺口**：据论文作者所知，**尚无先前工作对 Agent Skills 框架进行系统性安全分析**，这是本文试图填补的空白。

## 解决方案

论文通过**系统性分析框架构建**、**实证验证**与**分层防御策略**相结合的方式来解决 Agent Skills 的安全问题，具体方法如下：

## 1. 建立全生命周期攻击面分析框架（§4）

将 Agent Skills 框架分解为四个安全相关阶段——**创建（Creation）**、**分发（Distribution）**、**部署（Deployment）** 和 **执行（Execution）**，系统识别每个阶段引入的结构性攻击面：

- **创建阶段**：Skill 作者对指令文件和捆绑脚本的完全控制
- **分发阶段**：开放市场缺乏强制审查导致的供应链风险
- **部署阶段**：单次批准即授予持久化操作员级权限的同意差距（Consent Gap）
- **执行阶段**：提示注入与运行时权限滥用的实际发生场所

## 2. 构建分层威胁分类体系（§5）

基于架构分析和真实证据，构建包含**7大威胁类别**、**17种具体场景**的三层攻击模型（见图2和表3）：

| 攻击层 | 威胁类别 | 核心机制 |
|--------|---------|---------|
| **Layer 1：交付与信任建立** | T1 供应链妥协（Typosquatting、排名操纵、仓库劫持、幻觉包）<br>T2 同意滥用（同意差距、安装后修改） | 恶意 Skill 如何到达用户并获得受信权威 |
| **Layer 2：运行时攻击** | T3 提示注入（直接/间接注入）<br>T4 代码执行（恶意脚本、延迟依赖、远程代码获取）<br>T5 数据渗出（凭证收割、环境变量窃取、代码库渗出） | 已激活 Skill 对智能体及其环境的直接攻击 |
| **Layer 3：持久化与横向影响** | T6 持久化（记忆文件投毒、配置注入）<br>T7 多智能体传播（提示感染） | 妥协效应如何超越当前会话或智能体边界 |

## 3. 真实事件验证与映射（§6）

分析5起已确认的真实安全事件，验证分类体系的完备性：
- **MedusaLocker 勒索软件攻击**（T4.1, T2.1）：通过捆绑脚本执行勒索软件，利用同意差距
- **ClawHavoc 供应链攻击**（T5.1, T1.1, T1.2）：1,184个恶意 Skill 的大规模凭证窃取
- **CVE-2025-59536/CVE-2026-21852**（T5.1, T6.2）：通过配置注入实现 RCE 和 API 密钥渗出
- **SafeDep PEP 723 延迟依赖攻击**（T4.2）：利用未固定版本依赖的供应链攻击
- **Mitiga 静默代码库渗出**（T5.3, T1.2）：四次交互内完成完整代码库渗出

## 4. 提出分层防御方向（§7.1）

针对每个威胁类别讨论具体缓解策略，区分**立即可部署**与**需架构改革**的措施：

**供应链妥协（T1）**：
- 强制安全审查流程 + 加密来源验证（绑定命名空间与验证身份）
- 基于验证安装结果的声誉系统（替代原始下载计数）

**同意滥用（T2）**：
- **架构改革**：细粒度、按能力授权的权限模型（类似 Android 权限）
- **版本绑定信任**：将信任授予加密绑定到特定内容哈希，防止安装后修改继承权限

**提示注入（T3）**：
- 间接注入：将外部获取内容视为不可信并在进入上下文前进行清理
- 直接注入：需形式化行为规范（当前架构下无法完全解决）

**代码执行（T4）**：
- 基于能力层级的沙箱化（容器或 WebAssembly 隔离）
- 强制依赖固定（Dependency Pinning）和可重现构建

**数据渗出（T5）**：
- 基于能力声明的行为监控（要求 Skill 显式声明文件读取和网络端点）
- 区分合法数据传输与渗出的启发式监测

**持久化（T6）**：
- 对记忆文件和配置文件的完整性监控（加密校验和）
- 正常运行时只读挂载配置文件，修改需显式用户确认

**多智能体传播（T7）**：
- 智能体间信任边界强制：将对等智能体消息处理为用户层级而非操作员层级

## 5. 识别开放研究挑战（§7.2）

提出必须解决以建立成熟研究领域的**7大开放挑战**（C1-C7）：
- **C1**：自然语言指令分析（缺乏形式化行为规范框架）
- **C2**：同意模型设计（细粒度权限与可用性平衡）
- **C3**：运行时行为监控（无形式化规范下的异常检测）
- **C4**：大规模供应链完整性（自然语言内容的语义验证）
- **C5**：多智能体系统中的信任传播
- **C6**：自动化 Skill 审查（结合静态、动态和语义分析）
- **C7**：规范级安全属性（在保持灵活性的同时强制安全基线）

## 6. 提供利益相关者可操作建议（§7.3）

针对四类主体给出具体实践指导：
- **Skill 作者**：固定依赖版本、验证外部 URL、记录完整操作范围
- **市场运营商**：实施强制审查管道、命名空间治理、异常检测声誉系统
- **平台开发者**：扩展规范以强制类型化能力声明、实现版本绑定信任、运行时沙箱化
- **企业用户**：将 Skill 安装视为软件依赖管理问题，实施库存跟踪、安全审查和行为监控

通过这种**从架构分析到具体防御**的系统性方法，论文揭示了 Agent Skills 安全不能仅通过增量缓解解决，而需要架构层面的根本改革，为后续研究和工程实践提供了基础框架。

## 实验验证

本文作为一篇**愿景论文（Vision Paper）**，并未进行传统意义上的可控实验（如实现原型系统或大规模测量实验），而是通过**系统性架构分析**、**威胁分类构建**与**真实事件案例研究**相结合的方法进行验证。具体而言，论文完成了以下实证与分析工作：

## 1. 真实安全事件案例分析（§6）
论文对 Agent Skills 生态系统中 **5 起已确认的真实安全事件**进行了深度映射分析，以验证威胁分类体系的完备性：

| 事件 | 时间 | 映射的威胁类别 | 分析内容 |
|------|------|---------------|---------|
| **MedusaLocker 勒索软件攻击** | 2025年12月 | T4.1（恶意脚本）、T2.1（同意差距） | 分析 GIF 转换器 Skill 如何通过捆绑脚本静默下载并执行 MedusaLocker 勒索软件，揭示用户可见层与不可见执行层的分离机制 |
| **ClawHavoc 供应链攻击** | 2026年1月 | T5.1（凭证收割）、T1.1（Typosquatting）、T1.2（排名操纵） | 分析针对 ClawHub 市场的协调攻击，涉及 1,184 个恶意 Skill（约占当时生态系统的 1/5），研究其 typosquatting 技术和人工 inflated 下载量策略 |
| **CVE-2025-59536 / CVE-2026-21852** | 2026年2月 | T6.2（配置注入）、T5.1（凭证收割） | 分析 Check Point Research 披露的两个漏洞，研究通过 `.claude/settings.json` 注入 Hook 配置实现 RCE，以及通过修改 `ANTHROPIC_BASE_URL` 渗出 API 密钥的机制 |
| **SafeDep PEP 723 延迟依赖攻击** | 2026年1月 | T4.2（延迟依赖） | 演示如何利用 Python PEP 723 内联脚本元数据格式，通过未固定版本的依赖在运行时投递恶意负载 |
| **Mitiga 静默代码库渗出** | 2026年2月 | T5.3（代码库渗出）、T1.2（排名操纵） | 分析如何通过人工 inflated 声誉分数发布测试工具 Skill，在 4 次用户交互内完成完整代码库渗出且审计日志为空 |

**验证方法**：通过将每个事件映射到威胁分类体系（表4），证明所有事件均可被分类覆盖，且无事件需要新增类别，从而验证分类体系的**完备性**。

## 2. 架构驱动的结构分析（§3-§4）
论文对 Agent Skills 框架进行了**形式化的架构解构**，包括：
- **包结构分析**：解析 SKILL.md 的两部分结构（YAML frontmatter + Markdown instructions body），识别出缺乏数据-指令边界（data-instruction boundary）的结构性缺陷
- **渐进披露模型（Progressive Disclosure）分析**：建立三阶段加载模型的形式化描述（Level 1-3），定义元数据 $m_i$、指令 $inst_i$ 和补充文件 $f_{i,j}$ 的加载过程
- **信任模型分析**：识别"同意差距"（Consent Gap）——即安装时的授权对象（描述与可见内容）与实际权限范围（持久化、无差别的操作员级权威）之间的结构性错配

## 3. 外部实证数据的引用验证
论文引用了**其他研究团队的大规模实证研究**作为支撑证据（非本文实验）：
- **Liu et al. 的大规模扫描**：引用对 42,447 个 Skills 的扫描结果，显示 26.1% 包含至少一个安全漏洞，涵盖 14 种不同模式（提示注入、数据渗出、权限提升、供应链风险）
- **Snyk 的 ToxicSkills 研究**：引用对社区市场的安全分析，识别出装后修改（post-installation modification）和记忆文件投毒（memory file poisoning）攻击模式
- **Schmotz et al. 的注入实验**：引用关于 Skill 文件攻击（Skill-inject）的测量研究，证明三行 Markdown 文本即可实现有效注入

## 4. 威胁分类的构建方法（§5）
论文明确描述了分类体系的**三段式构建过程**：
1. **文献系统回顾**：审查已发表的 Agent Skills 及类似代理扩展机制的安全研究、安全公告、CVE 披露和实证研究，识别所有已记录的攻击模式
2. **架构原理分析**：从 Agent Skills 的设计属性（自然语言指令载体、渐进披露加载模型、单次批准信任授予、开放市场分发模型）出发，推理其引入的攻击面
3. **双向校准**： reconciling 文献证据与架构分析——结构分析识别但尚未观察到的场景若直接源于文档化架构属性则保留；观察到的场景则映射到结构性根本原因并相应分组

**总结**：本文的核心方法论是**基于架构的安全分析（Architecture-based Security Analysis）**与**案例研究验证**，而非实验验证。通过将抽象架构属性与具体真实事件相映射，建立了首个系统性的 Agent Skills 威胁分类体系。

## 未来工作

根据论文第7.2节（Open Challenges）及第7.1节（Defense Directions）的讨论，以下**七个方向**可作为进一步探索的核心研究点：

## 1. 自然语言指令的形式化分析与验证（C1）
**核心问题**：SKILL.md 文件以自然语言表达行为，缺乏形式化规范，无法静态分析其行为边界。
- **具体探索**：
  - 建立 Skill 行为的**形式化规范框架**（类似软件契约），使安全审计成为可能
  - 开发从自然语言指令中提取**行为特征**（文件访问、网络调用、子进程执行）的静态分析技术
  - 验证 Skill 实际行为与声明描述**一致性**的自动方法

## 2. 细粒度同意模型设计（C2）
**核心问题**：当前"全有或全无"的信任模型导致同意差距（Consent Gap），但细粒度权限又可能引发批准疲劳。
- **具体探索**：
  - 设计**分层权限模型**（如 Android 权限模型适配到 Agent 场景），平衡安全性和可用性
  - 开发**增量式同意机制**（Delta-based Consent）：仅在内容差异超过行为阈值时触发重新批准
  - 研究**用户认知负荷**与**安全有效性**之间的最优权衡点，避免用户因提示过多而盲目批准

## 3. 无规范前提的运行时行为监控（C3）
**核心问题**：无法通过静态规范定义合法行为时，如何检测运行时恶意活动。
- **具体探索**：
  - 基于**异常检测**的动作序列分析（建立正常行为基线）
  - **行为指纹**技术：对已知良性 Skill 的执行轨迹进行建模，识别偏离
  - **LLM-based 意图分类**：利用 LLM 实时评估智能体动作与当前 Skill 声明目的的一致性
  - 低误报率的**数据渗出检测**启发式算法（区分合法数据传输与恶意渗出）

## 4. 自然语言内容的供应链完整性（C4）
**核心问题**：现有供应链安全框架（如 in-toto、sigstore）针对二进制制品，无法验证自然语言指令的语义安全。
- **具体探索**：
  - 扩展供应链完整性框架以覆盖**自然语言内容的语义属性**（而非仅语法完整性）
  - 开发**作者签名+行为承诺**的混合验证机制
  - 针对开放贡献模型的**大规模自动化审查**技术，解决提交量过大导致人工审查不可行的问题

## 5. 多智能体系统中的信任传播（C5）
**核心问题**：智能体管道中，一个被妥协的智能体可通过提示感染（Prompt Infection）攻击下游智能体。
- **具体探索**：
  - 建立**跨智能体边界的信任传播模型**：当编排器委托子任务给子智能体时，权限应如何继承
  - 设计**消息来源验证机制**：确保智能体间通信的指令不被篡改
  - **特权层级强制**：将跨智能体消息处理为用户层级而非操作员层级，防止权限扩散

## 6. 自动化 Skill 审查管道（C6）
**核心问题**：市场规模的 Skill 数量使人工安全审查不可扩展。
- **具体探索**：
  - 结合**脚本静态分析**、**自然语言语义分析**（检测注入模式和能力声张过度）、**沙箱动态分析**的混合审查 pipeline
  - 低误报的**未知攻击技术检测**（超越基于签名的已知恶意模式匹配）
  - **依赖图分析**：验证声明依赖的存在性与完整性，检测幻觉包（Hallucinated Package）

## 7. 安全感知规范设计（C7）
**核心问题**：当前 Agent Skills 规范未包含安全保证或要求。
- **具体探索**：
  - 设计**强制能力声明机制**（Skill 必须显式声明文件访问、网络访问范围）
  - **版本绑定信任**的规范集成：将信任关系加密绑定到安装时的内容哈希
  - **依赖固定要求**（Dependency Pinning）的规范级强制
  - 在保持框架**表达灵活性**与强制**安全基线**之间的设计权衡研究

## 其他值得探索的具体技术问题
- **直接提示注入的防御**：在不破坏 Skill 功能的前提下，区分 SKILL.md 中的合法指令与对抗性注入（当前架构下尚无解决方案）
- **延迟依赖攻击的时序防御**：检测和阻止运行时依赖解析中的"先 benign 后恶意"替换模式
- **沙箱化的能力分层**：根据 Skill 声明的能力范围动态调整隔离级别（如文档处理 Skill 需要文件访问，但不应有网络访问）

## 总结

该论文针对 **Agent Skills**（2025年10月由Anthropic推出的LLM智能体能力扩展标准）开展了**首次系统性安全分析**，揭示其架构设计带来的结构性安全威胁，并构建威胁分类体系与防御框架。

### 1. 研究背景与核心问题
Agent Skills通过**自然语言指令文件（SKILL.md）**和**文件系统级代码包**实现能力扩展，已被Claude、Cursor、GitHub Copilot、Gemini CLI等平台采用，并形成数万级社区市场。然而，其架构特性引入了**质的不同于前代机制**（如ChatGPT Plugins、MCP）的安全风险：
- **无数据-指令边界**：自然语言指令与运行时数据无结构分离
- **单次批准持久信任**：一次安装即授予持久化操作员级权限，无后续确认
- **开放市场无审查**：缺乏强制安全审查，供应链攻击门槛低

### 2. 主要贡献

#### （1）全生命周期攻击面分析（§4）
将Agent Skills划分为四个安全阶段：
- **创建**：作者对指令和脚本的完全控制
- **分发**：Typosquatting、排名操纵、仓库劫持等供应链风险
- **部署**："同意差距"（Consent Gap）——用户授权对象（描述）与实际权限范围（持久化无差别操作权）的结构性错配
- **执行**：提示注入、代码执行、数据渗出

#### （2）三层威胁分类体系（§5）
构建涵盖**7大威胁类别**、**17种具体场景**的分类法（表3）：
- **Layer 1（交付与信任）**：供应链妥协（T1）、同意滥用（T2）
- **Layer 2（运行时攻击）**：提示注入（T3）、代码执行（T4）、数据渗出（T5）
- **Layer 3（持久化与横向）**：持久化（T6）、多智能体传播（T7）

#### （3）真实事件验证（§6）
分析5起已确认事件，验证分类完备性：
- **MedusaLocker**（2025年12月）：通过GIF转换器Skill执行勒索软件（T4.1, T2.1）
- **ClawHavoc**（2026年1月）：1,184个恶意Skill的大规模供应链攻击（T5.1, T1.1, T1.2）
- **CVE-2025-59536/21852**：配置注入导致RCE和API密钥渗出（T6.2, T5.1）
- **SafeDep PEP 723**：延迟依赖攻击（T4.2）
- **Mitiga静默渗出**：4次交互内完成代码库渗出（T5.3, T1.2）

### 3. 关键发现
- **结构性漏洞不可通过增量缓解解决**：最严重的威胁（提示注入、同意差距、供应链完整性）源于框架本身的结构属性，需要架构级改革
- **自然语言指令的不可判定性**：无法静态区分SKILL.md中的合法指令与对抗性注入，缺乏形式化行为规范
- **信任模型的根本性缺陷**：版本绑定缺失导致安装后修改可继承原始授权

### 4. 防御方向与开放挑战（§7）

#### 分层防御策略
- **供应链**：强制审查、加密来源验证、异常检测声誉系统
- **同意模型**：细粒度权限授权、版本绑定信任、增量式同意（Delta-based Consent）
- **运行时**：沙箱化（ capability-tiered ）、依赖固定、行为监控
- **持久化**：配置文件完整性监控、只读挂载

#### 七大开放研究挑战（C1-C7）
1. 自然语言指令的形式化分析与验证
2. 安全与可用性平衡的同意模型设计
3. 无规范前提的运行时行为监控
4. 自然语言内容的供应链完整性验证
5. 多智能体系统中的信任传播模型
6. 大规模自动化Skill审查管道
7. 安全感知的规范级安全属性设计

### 5. 结论
论文指出，随着自然语言能力规范成为智能体AI的主流范式，Agent Skills的安全部署需要超越"仅安装可信来源"的简单建议，必须通过**架构改革**（如强制能力声明、版本绑定信任、运行时沙箱化）与**生态系统治理**（如强制审查、命名空间验证）相结合，才能应对其固有的结构性安全风险。
