# Memori: A Persistent Memory Layer for Efficient, Context-Aware LLM Agents

**arXiv**: [2603.19935](https://arxiv.org/abs/2603.19935) · [PDF](https://arxiv.org/pdf/2603.19935)  
**领域**: Agent  
**作者**: Borro, Macarini, Tindall, Montero, Struck  
**综合评分**: 7.88  （novelty: 9.0 · method: 8.5 · evidence: 8.5 · clarity: 8.0）

---

## 摘要

> 本文提出了一种名为Memori的LLM无关的持久内存层，将内存视为数据结构问题，通过高级增强管道将非结构化对话转换为紧凑的语义三元组和对话摘要，实现了精确检索和连贯推理。在LoCoMo基准测试中，Memori以81.95%的准确率超越了现有内存系统，同时每个查询仅使用约5%的完整上下文令牌，显著降低了成本。该方法创新性地解决了LLM代理中持久内存的效率问题，实验证据充分，具有较好的通用性。

## 详细分析

> **社区热度**: ⭐ 2 (来自 papers.cool)

## 问题定义

这篇论文旨在解决**大型语言模型（LLM）智能体在长期、跨会话交互中面临的持久记忆管理难题**，具体包括以下核心挑战：

### 1. 上下文膨胀与成本问题
现有方法通过将大量原始对话历史直接注入提示词（prompt）来维持上下文，导致：
- **token成本急剧上升**：随着对话轮次增加，输入上下文呈线性增长，API调用成本高昂
- **上下文退化（Context Rot）**：过长的上下文窗口使模型倾向于忽略关键信息，产生不一致的输出，即使相关信息存在也无法有效利用

### 2. 非结构化数据的检索低效
原始对话日志包含大量噪声（口语化表达、寒暄、自我纠正、离题讨论等）：
- 传统RAG架构直接对原始文本进行分块和嵌入，导致向量空间混乱
- 检索结果包含大量无关信息，产生矛盾上下文，并在生成阶段消耗过多token

### 3. 供应商锁定与跨模型兼容性
现有记忆解决方案通常与特定LLM供应商绑定，缺乏**LLM无关（LLM-agnostic）**的通用记忆层，限制了智能体在不同模型间的迁移能力。

### 4. 记忆表示的结构化缺失
论文指出记忆不仅是**存储问题**，更是**结构化问题**：
- 需要将嘈杂的非结构化对话转换为高效的检索表示
- 需要在压缩信息的同时保留事实准确性、时序关系和叙事连贯性

### 解决方案概述
针对上述问题，论文提出**Memori**——一个持久记忆中间层，通过**Advanced Augmentation**流程将原始对话蒸馏为：
- **语义三元组**（subject–predicate–object）：捕获原子化事实
- **对话摘要**：保留时序背景和叙事脉络

这种双重表示实现了在仅使用**~5%原始上下文token**（平均1,294 tokens）的情况下，达到81.95%的准确率，显著降低了推理成本（比全上下文方法节省20倍以上），同时避免了传统长上下文带来的性能退化。

## 相关工作

根据论文引用及对比实验，相关研究可分为以下几类：

### 1. LLM智能体与记忆的综述性研究
- **Hu et al. (2025)** 在《Memory in the age of AI agents》中系统阐述了AI智能体时代记忆机制的重要性，指出记忆是实现通用智能的基础支柱。
- **Xi et al. (2025)** 通过综述《The rise and potential of large language model based agents》明确了现代智能体架构的关键组件：推理、规划、感知、记忆与工具使用。
- **Wang et al. (2024)** 在《A survey on large language model based autonomous agents》中分析了基于LLM的自主智能体设计范式。

### 2. 早期记忆系统架构
- **MemGPT (Packer et al., 2023)**：提出将LLM视为操作系统的理念，通过分层记忆管理（主上下文与外部存储的交互）实现长期记忆，但主要关注系统架构层面而非数据结构优化。
- **MemoryBank (Zhong et al., 2024)**：通过长期记忆存储与记忆更新机制增强LLM，支持跨会话信息保持，但缺乏对原始对话的结构化压缩处理。
- **Reflexion (Shinn et al., 2023)**：利用语言反馈进行强化学习，通过自我反思改善智能体行为，侧重于参数层面的经验积累而非外部记忆存储结构。

### 3. 上下文效率与退化研究
- **Hong et al. (2025)** 在《Context rot: How increasing input tokens impacts llm performance》中实证分析了"上下文退化"现象——即使相关信息存在于长上下文中，模型也难以有效利用，这为Memori的紧凑表示方法提供了理论动机。

### 4. 对比评估基准方法（Memori的直接竞争对手）
论文在LoCoMo基准上与以下开源记忆系统进行了直接对比：
- **Zep**：商业级记忆层，提供对话摘要与实体提取功能，但在实验中显示出较高的token消耗（3,911 tokens/查询）。
- **LangMem**：LangChain生态的记忆管理工具，支持时序推理但在单跳事实检索上表现较弱（74.47% vs Memori的87.87%）。
- **Mem0 (Chhikara et al., 2025)**：专注于生产级AI智能体的可扩展长期记忆，采用自适应记忆存储，但在LoCoMo基准上整体准确率较低（62.47%）。
- **MemR3 (Du et al., 2025)**：通过反思性推理进行记忆检索，代表了基于推理的记忆检索最新进展。

### 5. 评估基准
- **LoCoMo (Maharana et al., 2024)**：长对话记忆基准测试集，专门用于评估智能体在跨会话历史中进行状态跟踪、时序推理和微妙用户偏好检索的能力，是本文的核心评估工具。

这些研究表明，现有方案或依赖原始文本检索导致高token成本，或在结构化知识表示方面存在不足，而Memori通过**语义三元组+对话摘要**的双重结构表示，在保持LLM无关性的同时实现了更高的检索效率与成本效益。

## 解决方案

论文通过提出 **Memori** —— 一个 LLM 无关的持久记忆中间层——来解决上述问题。核心解决方案围绕**数据结构化**而非简单存储展开，具体实现分为以下几个层面：

### 1. 解耦式架构设计
Memori 作为独立记忆层部署于应用逻辑与底层 LLM 之间，通过轻量级 SDK 拦截请求并原生管理记忆。该设计实现了：
- **模型无关性**：记忆层与具体 LLM 供应商解耦，支持跨模型、跨会话的持久记忆
- **透明集成**：无需修改现有 LLM 客户端逻辑，通过包装器模式无缝接入

### 2. Advanced Augmentation：非结构化数据结构化
这是系统的核心创新，作为一个自动化认知过滤管道，将原始对话日志蒸馏为高密度、低噪声的记忆资产：

#### 语义三元组提取（Semantic Triples）
- **原子化知识表示**：将嘈杂的对话消息解构为 $(subject, predicate, object)$ 形式的语义三元组，捕获具体事实、用户偏好与约束条件
- **来源链接**：每个三元组精确链接到其起源的对话会话，建立事实与原始上下文的锚点
- **向量索引**：使用 Gemma-300 嵌入模型对三元组进行嵌入，构建低噪声、高信噪比的检索索引

#### 对话摘要生成（Conversation Summaries）
- **叙事连贯性保留**：针对三元组剥离上下文的问题，生成简洁的高层对话概述，捕获：
  - 用户的主导意图（overarching intent）
  - 对话的时间推进（chronological progression）
  - 任务的隐含背景（implicit context）
- **双重关联机制**：通过将原子三元组直接链接到其来源对话的摘要，确保检索到的事实习语始终可回溯至其宏观叙事背景，避免事实孤岛

### 3. 混合检索策略
在推理阶段，系统采用**混合搜索**（Hybrid Search）结合：
- **向量相似度**：基于嵌入的余弦相似度捕捉语义相关性
- **BM25 关键词匹配**：确保精确术语的召回

检索结果同时包含相关三元组及其关联的对话摘要，为 LLM 提供既精确又具上下文的证据链。

### 4. 上下文压缩与成本控制
通过结构化表示实现极致的上下文效率：
- **Token 压缩比**：平均仅需 $$1,294$$ 个 token 即可支撑单次查询，相当于全上下文（$$26,031$$ tokens）的 $$4.97\%$$
- **成本削减**：相比全上下文方法降低超过 $$20\times$$ 的 API 成本，相比 Zep 等竞争方案减少约 $$67\%$$ 的 token 消耗
- **规避上下文退化**：通过剔除对话噪声（寒暄、自我纠正、离题讨论），消除"上下文 rot"现象，确保关键信息不被长上下文淹没

### 5. 持续进化机制
Advanced Augmentation 作为后台管道持续运行，随着新对话的产生增量式地提取和更新记忆资产，使智能体能够：
- 累积跨会话的经验
- 跟踪用户状态的时序变化
- 在不重新处理全量历史的情况下更新知识库

这种"结构化即服务"（structuring-as-a-service）的范式将记忆管理从简单的文本存储转变为**知识工程**问题，证明了通过高质量的数据结构而非更大的上下文窗口，即可实现高效、可扩展的 LLM 智能体记忆。

## 实验验证

论文在 **LoCoMo（Long Conversation Memory）基准** 上开展了系统性实验，从记忆提取质量、推理能力到成本效率进行了多维度评估。实验设计如下：

### 1. 数据集与预处理
- **数据集**：采用 LoCoMo 基准 [Maharana et al., 2024]，该数据集专门用于测试智能体在跨会话长对话中的信息跟踪、保持与综合能力，包含复杂的状态跟踪、时序推理和深层用户偏好挖掘任务。
- **数据划分**：包含五类问题：Single-Hop、Multi-Hop、Temporal、Open-Domain 和 Adversarial。为确保与已有研究结果可比，实验**排除了 Adversarial 类别**（与 [Chhikara et al., 2025, Du et al., 2025] 保持一致）。
- **问题分布**：共计 1,529 个问题（Single-Hop: 830, Temporal: 321, Multi-Hop: 282, Open-Domain: 96）。

### 2. 记忆提取与索引（Advanced Augmentation 评估）
- **处理流程**：将 LoCoMo 的每个对话会话输入 Advanced Augmentation 管道，提取：
  - **语义三元组**：原子化事实的 $(subject, predicate, object)$ 表示
  - **对话摘要**：高层级的会话概述，保留时序与意图背景
- **向量化**：使用 **Gemma-300** 嵌入模型对提取的三元组进行嵌入
- **索引构建**：采用 **FAISS** 在本地构建索引，支持快速相似性搜索

### 3. 答案生成设置
- **模型**：使用 **GPT-4.1-mini** 作为生成模型
- **检索策略**：混合搜索（Hybrid Search），结合余弦相似度（向量搜索）与 BM25 关键词匹配
- **上下文构成**：检索到的相关三元组及其关联的对话摘要（通过溯源链接获取）
- **提示模板**：采用结构化提示（见 Appendix A），明确指导模型如何利用记忆和摘要进行时序计算与事实推理

### 4. 评估方法论
#### 4.1 LLM-as-a-Judge 评估框架
- **评判模型**：GPT-4.1-mini
- **评估维度**：对比生成答案与标准答案（Gold Answer），在二分类（CORRECT/WRONG）框架下评判事实准确性
- **评判标准**：
  - 对开放式问题，允许生成答案比标准答案详细，只要涵盖核心主题即判为正确
  - 对时序问题，允许相对时间（如"上周二"）与绝对时间（如"2023年5月7日"）的格式差异，只要指向同一时间点即判为正确
- **提示模板**：见 Appendix B，要求输出 JSON 格式标签

#### 4.2 Token 效率与成本分析
- **核心指标**：注入 LLM 提示词的绝对 token 数量（Added Tokens to Context）
- **成本计算**：基于 GPT-4.1-mini 定价（$0.8/1M tokens）计算单次查询成本
- **对比维度**：
  - 与 Full-Context（完整对话历史）方法对比，计算上下文占比（Context Footprint %）
  - 与主流记忆系统（Zep、Mem0）对比 token 消耗

### 5. 对比基线（Baselines）
实验对比了四类方法：
- **Full-Context (Ceiling)**：将完整对话历史注入提示，作为性能上限（但成本极高）
- **Zep**：开源记忆系统，提供实体提取与会话摘要功能
- **LangMem**：LangChain 生态的记忆管理工具
- **Mem0**：面向生产环境的自适应长期记忆系统

### 6. 实验结果与分析
#### 6.1 整体准确性（Table 1）
| Method | Single-hop (%) | Multi-hop (%) | Open-domain (%) | Temporal (%) | Overall (%) |
|:-------|:--------------:|:-------------:|:---------------:|:------------:|:-----------:|
| Memori | 87.87 | 72.70 | 63.54 | 80.37 | **81.95** |
| Zep | 79.43 | 69.16 | 73.96 | 83.33 | 79.09 |
| LangMem | 74.47 | 61.06 | 67.71 | 86.92 | 78.05 |
| Mem0 | 62.41 | 57.32 | 44.79 | 66.47 | 62.47 |
| Full-Context | 88.53 | 77.70 | 71.88 | 92.70 | 87.52 |

- **关键发现**：Memori 在检索类系统中取得最高整体准确率（81.95%），较 Zep 提升 2.86 个百分点，较 Mem0 提升 19.48 个百分点，同时将上下文压缩至全量的 4.97%。

#### 6.2 分维度性能（Figure 2）
- **Single-Hop（87.87%）**：直接事实检索能力最强，显著优于 LangMem（74.47%）和 Zep（79.43%），证明结构化三元组在消除噪声、精确定位事实方面的优势。
- **Multi-Hop（72.70%）**：多跳推理表现优于 Zep（69.16%）和 LangMem（61.06%），显示三元组与摘要的结合有助于连接分散信息。
- **Temporal（80.37%）**：时序推理优于 Mem0（66.47%），但略低于 LangMem（86.92%）和 Zep（83.33%），表明孤立三元组在捕获状态变化时序方面仍有改进空间。
- **Open-Domain（63.54%）**：开放域问答对所有检索系统均具挑战性，Memori 略低于 LangMem（67.71%），但论文指出此类问题通常需要检索更大文本块，与系统最小化 token 的核心目标存在张力。

#### 6.3 成本效率（Table 2）
| Method | Added Tokens (mean) | Context Cost ($) | Context Footprint (%) |
|:-------|:-------------------:|:----------------:|:---------------------:|
| Memori | **1,294** | **0.001035** | **4.97** |
| Full-Context | 26,031 | 0.020825 | 100.00 |
| Mem0 | 1,764 | 0.001411 | 6.78 |
| Zep | 3,911 | 0.003129 | 15.02 |

- **成本削减**：Memori 较 Zep 减少 **67%** 的 token 消耗，较 Full-Context 降低 **20 倍以上**成本，同时保持更高的准确率。
- **稳定性**：实验重复运行 3 轮（$n=3$），报告平均准确率及标准差（Figure 2 误差棒），结果具有一致性。

### 7. 消融与机制验证
- **结构化 vs 非结构化**：通过对比 Memori（结构化三元组+摘要）与 Full-Context（原始文本），验证了高质量结构化记忆可在极小上下文占比（4.97%）下接近全上下文性能（81.95% vs 87.52%）。
- **双重表示有效性**：分析表明，单纯依赖三元组会丢失时序背景（Temporal 得分低于预期），而单纯依赖摘要会牺牲事实精度，两者结合实现了最佳平衡。

## 未来工作

基于论文的实验结果与系统架构，以下方向值得进一步探索：

### 1. 时序推理机制的强化
论文显示 Memori 在 **Temporal** 类别（80.37%）落后于 LangMem（86.92%）与 Zep（83.33%），表明孤立的三元组难以捕获用户状态的动态演变。未来研究可探索：
- **时间感知的图神经网络（Temporal GNN）**：将三元组建模为时序知识图谱，利用关系的时间戳边捕获状态转移（如"偏好从A变为B"）
- **显式的时间推理模块**：在检索阶段引入专门的时序推理器，处理相对时间表达式（如"两年前"→具体年份的转换逻辑）
- **差分记忆表示**：不仅存储当前状态，还存储状态间的差异（deltas），显式建模变化而非仅依赖摘要的隐式叙事

### 2. 开放域问答的自适应检索策略
**Open-Domain** 类别表现相对较弱（63.54%），此类问题需要跨大量上下文的广泛综合而非原子事实。可探索：
- **动态上下文扩展机制**：根据问题类型自适应调整检索粒度——对事实性问题使用三元组，对开放域问题自动扩展至原始文本片段或更粗粒度的会话块
- **层次化记忆架构**：构建"摘要→三元组→原始文本"的三层检索体系，通过顶层导航逐层钻取细节，平衡压缩率与信息完整性

### 3. 记忆冲突与不确定性管理
当前实现仅简单优先选择"最新记忆"处理矛盾信息。更复杂的场景需要：
- **置信度加权机制**：为每个三元组附加提取置信度与来源可靠性分数，在冲突时进行概率推理而非硬性覆盖
- **矛盾检测与澄清策略**：当检测到高度冲突（如用户在不同时间表达截然相反的偏好）时，主动生成澄清问题而非武断选择，将记忆维护转化为交互式过程

### 4. 跨模态记忆扩展
当前系统仅处理文本对话。扩展至**多模态智能体**需解决：
- **多模态语义三元组**：将图像、视频内容转换为结构化表示（如"用户[展示]→[红色连衣裙]"），并保持跨模态链接
- **模态感知的检索融合**：设计机制平衡文本三元组与视觉记忆的检索权重，处理"用户上次展示的物体是什么颜色"这类跨模态查询

### 5. 记忆隐私与联邦化
持久记忆涉及敏感用户数据，可探索：
- **联邦记忆学习**：在保护隐私前提下，跨多个用户会话学习公共知识模式（如常见任务流程），同时保持用户特定事实的本地隔离
- **差分隐私注入**：在记忆提取阶段向三元组添加可控噪声，确保即使记忆泄露也难以逆向还原原始对话内容

### 6. 与参数记忆的混合架构
论文强调外部记忆的重要性，但未来可探索**双记忆系统**的协同：
- **动态路由机制**：判断查询应使用外部记忆（Memori）、模型参数知识，还是两者结合（如使用 Memori 检索上下文进行上下文学习以触发参数中的相关模式）
- **记忆固化（Memory Consolidation）**：将高频访问的记忆三元组通过微调或 LoRA 适配器逐步整合到模型参数中，减少对外部检索的依赖，形成"显性记忆→隐性记忆"的转化

### 7. 评估方法的客观化
当前依赖 **LLM-as-a-Judge** 可能存在评估偏差。改进方向包括：
- **基于规则的自动评估**：针对时序问题设计可验证的逻辑检查器（如自动解析日期表达式进行等价性判断）
- **人工-自动化混合评估**：建立细粒度标注体系，区分"事实正确但缺失上下文"与"完全错误"的灰色地带，而非简单的二分类标签

### 8. 实时记忆更新的计算优化
**Advanced Augmentation** 作为后台管道，其延迟与计算成本在超大规模会话场景下可能成为瓶颈：
- **增量式三元组提取**：设计流式算法，仅对新输入消息进行局部更新，而非重新处理整个会话窗口
- **边缘计算部署**：将轻量级记忆提取模型（如小型 SLM）部署在边缘设备，实现近实时的记忆更新而无需云端重计算

### 9. 用户可控的记忆编辑
当前记忆系统为黑盒自动提取。赋予用户控制权：
- **记忆审计接口**：允许用户查看、编辑、删除特定三元组，纠正误解（如"系统误认为我喜欢辣食，实际我不吃辣"）
- **遗忘机制**：实现有针对性的记忆抹除（selective forgetting），满足 GDPR 等法规的"被遗忘权"要求，同时保留不相关的其他记忆

这些方向在保持 Memori 核心优势（结构化、低成本、LLM 无关）的同时，可针对性地弥补当前在时序推理、开放域泛化及隐私保护方面的局限。

## 总结

本文提出 **Memori**，一种面向大型语言模型（LLM）智能体的持久记忆中间层，旨在解决跨会话、跨模型场景下的上下文感知难题。以下是论文的主要内容概括：

### 1. 研究背景与核心问题
随着LLM智能体向通用智能演进，**持久记忆**成为关键支柱。现有方案面临三重挑战：
- **上下文膨胀**：将原始对话历史直接注入提示导致token成本指数级增长
- **上下文退化（Context Rot）**：长上下文使模型难以有效利用关键信息，产生不一致输出
- **结构缺失**：传统RAG直接对嘈杂文本分块嵌入，检索效率低且包含大量无关信息

核心洞察：**记忆管理的本质是数据结构问题，而非单纯存储问题**。

### 2. 系统架构：Memori
Memori作为**LLM无关**的解耦记忆层，部署于应用逻辑与底层模型之间，通过轻量级SDK透明拦截请求。其核心创新在于**Advanced Augmentation**——一个自动化的认知过滤管道，将非结构化对话蒸馏为高密度记忆资产：

#### 2.1 双重记忆表示
- **语义三元组**（$subject\text{--}predicate\text{--}object$）：提取原子化事实与用户偏好，构建低噪声、高信噪比的向量索引
- **对话摘要**：捕获会话的时序脉络、用户意图演变与任务背景，弥补三元组缺乏的叙事连贯性

通过将每个三元组精确链接至其来源会话的摘要，系统确保**原子事实**与**宏观语境**始终关联，避免事实孤岛。

#### 2.2 混合检索机制
结合向量相似度（余弦相似度）与BM25关键词匹配，实现精准召回。检索结果同时包含相关三元组及其关联摘要，为推理提供既精确又富上下文的证据链。

### 3. 实验验证
在**LoCoMo**（Long Conversation Memory）基准上进行评估，该数据集专门测试跨会话的状态跟踪、时序推理与深层偏好检索能力。

**实验设置**：
- 对比基线：Zep、LangMem、Mem0及Full-Context（全对话注入，作为性能上限）
- 评估模型：GPT-4.1-mini
- 评判方法：LLM-as-a-Judge（二分类：CORRECT/WRONG）
- 关键指标：分类准确率（Single-Hop、Multi-Hop、Temporal、Open-Domain）与上下文token消耗

### 4. 主要结果

#### 4.1 推理性能
Memori在检索类系统中达到**最优整体准确率81.95%**（接近Full-Context的87.52%）：

| 推理类别 | Memori | 次优基线 | 关键优势 |
|:---------|:------:|:--------:|:---------|
| Single-Hop | 87.87% | Zep (79.43%) | 结构化三元组消除噪声，实现精准事实定位 |
| Multi-Hop | 72.70% | Zep (69.16%) | 三元组与摘要结合支持跨事实关联推理 |
| Temporal | 80.37% | LangMem (86.92%) | 摘要提供时序背景，但仍有改进空间 |
| Open-Domain | 63.54% | LangMem (67.71%) | 开放域综合需要更粗粒度信息，与极简token目标存在张力 |

#### 4.2 成本效率
Memori实现**极致的上下文压缩**：
- 平均仅需 **$1,294$** 个token（占全上下文的 **$4.97\%$**）
- 较Zep（$3,911$ tokens）减少 **$67\%$** 的token消耗
- 较Full-Context（$26,031$ tokens）降低 **$20$ 倍以上** 的API成本
- 在显著降低成本的同时，准确率超越所有对比的记忆系统

### 5. 核心贡献
- **范式转变**：证明通过高质量结构化表示（语义三元组+摘要）而非更大上下文窗口，即可实现高效、准确的LLM记忆
- **成本效益**：消除了推理质量与运营成本之间的传统权衡，使长周期、跨会话的智能体部署在经济上可行
- **实用架构**：提供LLM无关、即插即用的记忆层，支持生产环境中的可扩展部署
