## 摘要

> 本文提出了一种名为Egocentric Co-Pilot的Web原生神经符号框架，用于在智能眼镜上运行，通过大语言模型（LLM）协调感知、推理和网络工具，实现第一人称视角下的长期问答和决策支持。论文创新性地结合了时序思维链（Temporal Chain-of-Thought）与分层上下文压缩（Hierarchical Context Compression）来处理连续的第一人称视频，超越了单一模型的上下文窗口限制。实验在Egolife和HD-EPIC数据集上展示了具有竞争力的性能，并通过人机交互研究验证了其在实际智能眼镜应用中的优越性。

## 问题定义

这篇论文试图解决构建**第一人称视角（egocentric）智能助手**时所面临的核心技术挑战，特别是针对智能眼镜等可穿戴设备的应用场景。具体而言，论文识别并试图解决以下四个关键问题：

### 1. **单一大模型的局限性与专业化推理需求**
现有的端到端多模态大语言模型（Monolithic MLLMs）在需要**精确符号推理**的专门任务上表现不佳（如策略棋盘游戏、复杂日程规划）。这些模型往往产生回避性、模糊或"幻觉"式的回答（如"这看起来像是暗棋……"），无法提供可执行、精确的解决方案。论文指出，单一模型难以同时胜任开放域理解与精确符号计算。

### 2. **现实世界交互的多模态歧义性**
在物理环境中，用户指令（如"帮我分析这个"、"再看看这个"）往往具有**指代歧义性（deictic ambiguity）**。系统必须将模糊的自然语言与嘈杂的视觉输入（手势、视线方向）结合，才能准确理解用户意图。现有系统缺乏有效的机制来实时消解这种多模态歧义，容易导致误解，这在辅助性场景中尤为危险。

### 3. **连续第一人称视频的长时序上下文管理**
智能眼镜产生的是**连续、长程的第一人称视频流**，而现有模型受限于有限的上下文窗口，难以：
- 维护跨越数小时的长程依赖关系
- 在实时流中保持对过去事件的"记忆"
- 处理长视频中的细粒度时间推理（如"在16:37到16:46之间添加了哪些食材？"）

### 4. **资源受限设备上的实时Web原生部署**
如何在计算、电池和散热受限的智能眼镜上，实现**低延迟、高可靠性**的AI辅助？论文关注如何构建一个既可利用云端强大计算能力，又能通过Web原生协议（WebRTC/WebSocket）实现实时双向通信的系统，同时满足隐私保护和可访问性需求（针对低视力、认知障碍等群体）。

### 核心解决思路
为此，论文提出 **Egocentric Co-Pilot** 框架，通过**神经符号架构（neuro-symbolic architecture）**和**LLM编排（LLM Orchestration）**来解决上述问题：
- 使用**时序思维链（T-CoT）**和**分层上下文压缩（HCC）**处理长视频流
- 通过**工具调用（Tool Use）**将专门任务（如棋盘识别、搜索引擎、日历API）委托给特定模块，而非依赖单一模型
- 采用**3D射线投射**和**主动澄清（Proactive Clarification）**机制消解多模态歧义
- 基于**WebRTC**构建云原生实时通信管道，平衡延迟与计算需求

## 相关工作

该论文在第2节"Related Work"中系统梳理了四个相关研究领域：

## 1. 第一人称视角人工智能（Egocentric Artificial Intelligence）

该领域已从基础任务（动作识别、手-物交互、视觉情感分析）演进至基于多模态大语言模型（MLLMs）的复杂推理。现有研究在以下方面存在局限：

- **长视频处理瓶颈**：Transformer模型的计算成本与上下文窗口限制阻碍了长视频理解
- **现有解决方案**：包括将视频转换为文本日志、分层建模、层次化检索智能体等
- **关键差异**：现有工作多聚焦于**离线分析**，而本文针对**实时连续 lifelogging**场景，需在资源受限设备上处理连续视频流

## 2. LLM驱动的智能体与工具使用（LLM-driven Agents and Tool Use）

- **核心范式**：LLM作为中心控制器，通过"思维-行动"循环（thought-action loop）进行推理、规划并与外部工具交互
- **代表框架**：LangChain、AutoGPT等简化了开发流程，但在可靠性、长程规划与泛化能力方面仍存挑战
- **应用领域演进**：
  - 数字领域：网页导航（WebArena、Mind2Web等）
  - 物理具身智能体：机器人任务规划（SayCan、AutoTAMP等）
- **本文定位**：专注于**非机器人可穿戴智能体**（"Egocentric Co-Pilot"），作为增强人类行为的协作伙伴，而非替代人类操作

## 3. 神经符号系统（Neuro-Symbolic Systems）

- **核心思想**：结合神经网络感知能力与符号推理的精确性，缓解各自缺陷（神经网络的黑箱性 vs. 符号方法对噪声数据的脆弱性）
- **近期进展**：学习非结构化数据同时受显式符号知识约束的系统
- **架构差异**：本文采用**分层模块化**设计，将神经符号管道封装为**离散可调用的工具**（discrete, callable tools），由LLM通过MCP（Model-Context Protocol）协议编排，而非构建紧耦合的单体系统

## 4. 多模态意图消解（Multimodal Intent Disambiguation）

- **演进路径**：从结构化对话系统发展到LLM驱动的方法，但多数仍局限于**非具身、纯文本场景**
- **第一人称视觉（EGV）的特殊挑战**：
  - 用户输入固有的噪声与模糊性（特别是指向手势）
  - 现有工作常被动处理或过度简化手势模态
  - 即使最先进的VLM在空间推理方面仍不可靠，易产生幻觉（hallucinations）
- **混合架构趋势**：结合LLM推理与专门模块进行视觉定位
- **本文贡献**：提出**主动、迭代式框架**，通过实时交互引导用户消解多模态歧义，而非事后被动分析噪声输入

此外，论文还提及了**WebRTC与实时通信基础设施**（LiveKit等）、**上下文压缩与长文本建模**（Hierarchical Context Compression相关方法）以及**可穿戴计算与辅助技术**等领域的相关工作基础。

## 解决方案

论文通过 **Egocentric Co-Pilot** 框架解决上述挑战，该框架由四个协同工作的核心模块构成：

---

### 1. 第一人称推理核心（Egocentric Reasoning Core）

针对**长视频流上下文管理**问题，论文提出双层次时序处理策略，核心是一个基于多模态大语言模型（MLLM）的引擎 $M_{vqa}$。

**统一事件日志构建**  
系统维护一个按时间排序的统一事件日志 $E$，其中每个事件 $e_i = (t_i, m_i, c_i)$ 包含时间戳、模态（视觉/语音）与归一化内容。视觉事件通过以 1 FPS 采样的第一人称视频经微调后的 Qwen2.5-VL-7B-Instruct 模型生成密集描述，与 ASR 转录的语音查询融合。

**时序思维链（Temporal Chain-of-Thought, T-CoT）**  
针对短期细粒度分析，T-CoT 通过程序化的时序窗口选择机制，围绕相关时间戳裁剪或拼接视频片段，构建连贯的局部叙事线。对于多个片段，系统将其连接为单一时间线并重新归一化时间戳；对于超长单视频，则生成顺序片段的文本摘要作为上下文。

**分层上下文压缩（Hierarchical Context Compression, HCC）**  
针对超出模型上下文窗口的长程依赖，HCC 将历史日志划分为时间块（如每小时），使用纯文本 LLM 评估各块与查询的相关性，并仅对相关块生成查询感知的简洁摘要。这些摘要被前置到 T-CoT 上下文中，形成：
$$C_{final} = \text{HCC}(E_{historical}, Q) \oplus \text{T-CoT}(E_{recent}, Q)$$
其中 $\oplus$ 表示上下文拼接。

**鲁棒答案生成**  
采用正则表达式解析器从自由格式输出中提取答案选项，并通过五种不同语法提示的多数投票（majority voting）机制增强鲁棒性。

### 2. LLM 编排的神经符号执行（LLM-Orchestrated Neuro-Symbolic Execution）

针对**单一大模型在专业任务上的局限性**，论文采用模块化工具调用架构，通过 **Model-Context Protocol (MCP)** 实现。

**MCP 协议与执行循环**  
MCP 是一种轻量级 JSON-Schema 描述的函数接口，支持在标准 Web 通道（WebRTC 数据通道或 HTTPS）上运行。执行遵循检索-行动循环：
1. **发现**：LLM 通过 `MCP.ListTools()` 获取可用工具集 $T_{available}$
2. **规划**：LLM 基于用户查询 $Q$ 和多模态上下文 $C_{mm}$ 生成工具调用计划 $tool_{plan}$
3. **执行**：顺序或并行调用工具 $MCP.CallTool(T_{selected}, Args)$，更新执行上下文
4. **合成**：LLM 基于执行结果合成最终响应 $R_{final}$

**神经符号工具示例：棋盘游戏助手**  
以物理棋盘游戏辅助为例，该工具封装了完整的神经符号管道：
- **感知模块（神经）**：将第一人称棋盘视图映射到稳定的符号状态（如 FEN 记谱法）。通过时序缓冲机制抑制帧级检测噪声，承诺状态 $P_{r,c}$ 由多数投票稳定性阈值 $\tau$ 决定：
$$
P_{r,c} = 
\begin{cases} 
\arg\max_k \sum_{i=1}^N V_{r,c,k}^{(i)} & \text{if } \frac{1}{N}\max_k \sum_{i=1}^N V_{r,c,k}^{(i)} \geq \tau \\
P_{r,c}^{prev} & \text{otherwise}
\end{cases}
$$
其中 $V_{r,c,k}^{(i)}$ 为位置 $(r,c)$ 在帧 $i$ 的检测结果，$N$ 为缓冲大小。
- **符号引擎（符号）**：确定性国际象棋引擎评估合法着法
- **语义解释器（LLM）**：将引擎输出的坐标转换为适合玩家水平的战略自然语言指导

**运行时防护机制**  
- **允许列表（Allowlist）**：仅限非破坏性能力（如查询回答），禁止直接控制执行器
- **模式验证**：MCP 在调用前验证参数是否符合类型注解的模式
- **用户确认**：对具有副作用的操作（如编辑日历），系统要求自然语言确认提示

### 3. 设备端感知与 WebRTC 交互（On-Device Perception and WebRTC-Based Interaction）

针对**资源受限设备上的实时部署**，论文设计了低延迟的 Web 原生通信架构。

**设备端流水线**  
在智能眼镜的单事件循环中并行处理：
- **音频流水线**：轻量级能量-based VAD（Voice Activity Detection）带预滚动缓冲（pre-roll buffer），支持全双工打断检测（barge-in）。增益 $g=5.0$ 应用于音频块以提升信噪比
- **视频流水线**：裁剪与下采样第一人称视频流后编码传输

**WebRTC 云原生后端**  
采用 LiveKit 实现标准 WebRTC 协议栈，统一传输：
- 音频：Opus 编码
- 视频：H.264 编码  
- 控制：数据通道传输对齐元数据与工具调用信号

服务端语音流水线代理组合神经 VAD、流式 ASR、多模态 LLM 与 TTS，配置为全双工、可中断操作：
$$I_{webrtc} = F_{vad} \circ F_{asr} \circ F_{llm} \circ F_{tts}$$

**替代基线**  
同时部署本地 WebSocket 变体作为对比，展示云卸载与本地推理在延迟、移动性和资源使用间的权衡。

---

### 4. 主动多模态意图消解（Proactive Multimodal Intent Disambiguation）

针对**多模态指令的歧义性**，论文在交互管道末端集成轻量级澄清模块。

**决策框架**  
当 LLM 检测到高语义不确定性或冲突解释时，模块将情况重构为约束决策问题。给定输入 $(x_{1:t}, v_{1:t}, s_t)$ 和候选解释集 $\{\phi_k\}$，系统选择直接回答或请求澄清：
$$\phi^* = \arg\max_{\phi_k \in \Phi \cup \{ask\}} U(\phi_k | x_{1:t}, v_{1:t}, s_t)$$
其中 $U(\cdot)$ 权衡信息增益与交互成本。

**3D 射线投射指向消解**  
对于"分析这个"等指示性命令，系统使用 **3D 射线投射（raycasting）** 方法：
- 基于手部姿态估计发射射线（原点 $hand_{position}$，方向 $finger_{vector}$）
- 在 cluttered 场景中通过几何投影确定用户指向的具体对象
- 若置信度不足，主动发起简短跟进问题（如"您指的是左边的棋子还是角落的那个？"）

**零样本适配**  
该模块作为即插即用（plug-and-play）的包装器，无需重新训练基础模型，可针对导航辅助、日常协助等敏感域选择性启用。

### 整合流程

完整系统的工作流程如下：
1. **输入处理**：语音经 ASR 转录，视频经 VAD 触发捕获，通过 WebRTC 传输至云端
2. **意图消解**：若存在歧义，触发澄清对话；否则进入推理核心
3. **上下文构建**：HCC 提供长程记忆，T-CoT 提供短期细粒度上下文
4. **工具编排**：LLM 通过 MCP 选择并调用神经符号工具（如棋盘识别+引擎查询、营养 API、日历 API）
5. **响应生成**：LLM 综合工具返回的结构化数据，生成自然语言响应，经 TTS 合成语音回传设备

该架构通过**模块化分工**（感知-符号-交互解耦）、**分层记忆管理**（HCC+T-CoT）和**Web 原生设计**（WebRTC/MCP），在资源受限的可穿戴设备上实现了长程、精确、可解释的第一人称辅助。

## 实验验证

论文在第四节（Section 4）中开展了四组主要实验，系统验证了框架在基准数据集和真实世界场景中的性能：

### 1. 第一人称问答基准测试（Egocentric QA Benchmarks）

在标准的第一人称视频问答基准上评估 **Reasoning Core** 的长程推理能力：

- **数据集**：
  - **Egolife**：包含长程连续视频，需要跨越数小时的历史推理
  - **HD-EPIC**：专注于动作中心的短片段，强调细粒度时间推理

- **对比基线**：与当前最先进的模型进行对比，包括 LLaVA-OV、GPT-4o、Gemini-1.5-Pro、Qwen2.5 VL、VideoLlama 2、LongVA 等

- **关键策略**：
  - 对 Egolife 使用 **Hierarchical Context Compression (HCC)** 处理长历史
  - 对 HD-EPIC 使用 **Temporal Chain-of-Thought (T-CoT)** 处理动作片段

- **结果**：在 Egolife 上达到 **40.9%** 准确率（超越 Qwen2.5 VL 的 38.1%），在 HD-EPIC 上达到 **46.2%**（显著优于 Gemini-1.5-Pro 的 37.6%）

### 2. 消融实验与敏感性分析（Ablation and Sensitivity Analysis）

通过逐项移除组件，量化各模块对系统性能的贡献：

| 数据集 | 变体 | 准确率 | 性能下降 |
|--------|------|--------|----------|
| **Egolife** | 完整模型 | 40.9% | - |
| | 移除 Fine-tuning | 39.2% | -1.7 |
| | 移除 T-CoT | 39.5% | -1.4 |
| | 移除 HCC | 38.9% | -2.0 |
| | 移除 Transcript | 40.1% | -0.8 |
| **HD-EPIC** | 完整模型 | 46.23% | - |
| | 移除 Fine-tuning | 40.61% | -5.62 |
| | 移除 T-CoT | 42.68% | -3.55 |
| | 移除 HCC | 41.55% | -4.68 |
| | 移除 Pre-Processing | 43.56% | -2.67 |

**关键发现**：
- HCC 对长视频理解至关重要（Egolife 上移除导致 -2.0，HD-EPIC 上 -4.68）
- 领域特定的微调在 HD-EPIC 上尤为重要（-5.62）
- 提示工程与后处理（Pre-Processing）等"工程细节"对鲁棒性有显著影响（-2.67）

此外还测试了 HCC 的超参数敏感性：将摘要长度减半或块大小加倍仅导致 1.0–1.6 个百分点的下降，表明框架对参数变化具有合理鲁棒性。

### 3. 真实世界场景中的工具使用（Tool Use in Real-World Scenarios）

在智能眼镜上部署端到端系统，评估 **LLM 编排的神经符号框架** 在实际交互中的表现：

- **评估指标**：任务完成率（Task Completion Rate, TCR），定义为无需人工干预即可成功执行任务的比例

- **任务分类**：
  - **类别 1：基础工具使用**（Foundational Tool Use）
    - 场景：查询知识库（"查询这个苹果的卡路里"）、管理日程（"提醒下午3点会议"）、创建笔记
    - 结果：**98.5%** TCR，验证了核心执行循环的可靠性

  - **类别 2：具身策略与时空任务**（Embodied Strategy and Spatiotemporal Tasks）
    - 场景：物理棋盘游戏辅助（如国际象棋、中国象棋）
    - 技术：视觉模块映射棋盘状态 → 符号引擎搜索 → LLM 生成战略指导
    - 结果：在 50 局游戏中达到 **98%** 的端到端成功率

  - **类别 3：复杂神经符号推理**（Complex Neuro-Symbolic Reasoning）
    - 场景：结合噪声视觉输入与确定性符号求解器的专家级任务
    - 验证：感知模块、符号引擎与语义解释器的协同工作能力

- **失效分析（Failure Analysis）**：人工检查失败案例，主要归类为四类：
  1. **感知错误**：棋盘状态误检、复杂场景中目标物误定位
  2. **意图误解**：LLM 过度泛化上下文、指示性指代解析错误
  3. **工具级问题**：参数缺失或 API 异常响应
  4. **长程记忆错误**：相关历史事件在压缩上下文中被遗漏

### 4. 人在回路评估（Human-in-the-Loop Evaluation）

对比 **Egocentric Co-Pilot** 与主流商用智能眼镜及人类基线的实际用户体验：

- **实验设计**：
  - 采用**受控离线协议**：录制各系统（包括 Rabbit r1、Xiaomi Smart Audio Glasses、RayNeo 系列、Apple Vision Pro、Ray-Ban Meta 等）在相同提示和环境下的交互日志（音频、视频、转录）
  - 评估者盲测：独立评分者观看匿名化、随机排序的交互片段，使用 **5 点李克特量表**（越高越好）评估：
    - 多模态意图理解的准确性
    - 任务执行的成功率

- **结果**：
  - **主观评分**：Egocentric Co-Pilot 获得 **4.70** 分（人类基线为 4.90），显著优于所有商用设备（最佳竞品为 Apple Vision Pro 的 4.61，多数设备在 3.77–4.53 之间）
  - **客观 TCR**：Egocentric Co-Pilot 的端到端任务完成率高于所有单独的设备基线

- **伦理说明**：该研究使用预录制的匿名化日志进行低风险日常任务评估（如天气查询、简单规划、游戏建议），被机构归类为"最小风险"类别，参与者均签署知情同意书。

### 补充实验（附录中）

- **与 EgoGPT 的对比**（Appendix C）：EgoGPT 采用多阶段检索增强生成（RAG+）管道，在 Egolife 上达到 42.6%，但其需要多次离线推理遍历整个数据集，与本文关注的低延迟、始终在线的流式处理不直接可比。

- **WebRTC vs WebSocket 基线**（Section 3.3 & Appendix E）：对比了云原生 WebRTC 管道与本地 WebSocket 变体在延迟、移动性和资源消耗方面的权衡。

## 未来工作

基于论文第5节"局限性与未来工作"以及实验分析中的讨论，可进一步探索的研究方向包括：

---

### 1. 形式化安全机制与系统鲁棒性
当前系统依赖允许列表（allowlist）、模式验证（schema validation）和显式确认等运行时防护机制，这些措施弱于形式化安全保证。未来需探索：
- **能力管理（Capability Management）**：建立细粒度的每应用策略（per-application policies），限制工具访问权限
- **事务语义（Transactional Semantics）**：实现事务性的提交/中止（commit/abort）机制，确保多工具计划的原子性执行与自动回滚
- **故障恢复优化**：针对感知错误、意图误解、工具级异常等失效模式（第4.3节），开发更强的参数验证和错误恢复策略

---

### 2. 边缘-云协同与资源优化
现有架构依赖云后端和领域特定的微调模型，面临延迟、能耗与泛化性挑战：
- **参数高效适应（Parameter-Efficient Adaptation）**：探索 LoRA、Adapter 等技术，使模型能快速适应新领域或相机形态，而无需完整微调
- **设备端轻量化模型**：部署具备足够推理能力的本地模型，减少连续流式传输的带宽与能耗开销，实现离线降级（offline fallback）能力
- **计算-能源足迹核算**：建立跨部署选项（纯云端、混合式、纯边缘）的显式资源消耗评估框架，优化电池续航（当前约20分钟）与热管理

---

### 3. 隐私保护架构与伦理部署
持续第一人称视频采集引发隐私与旁观者同意问题：
- **隐私优先的混合架构**（Appendix E.2）：敏感视觉数据（如人脸、文本）在边缘设备本地处理或掩码，仅向云端传输非敏感的抽象特征（如边界框、语义标签）
- **实时隐私过滤**：开发设备端的隐私保护训练与推理机制，确保符合 Web 规模部署的隐私规范
- **旁观者同意机制**：探索视觉指示灯、音频提示或选择性像素化技术，解决公共空间中的第三方隐私问题

---

### 4. 长期纵向研究与多样化人群评估
当前评估局限于短期任务与健康成年受试者：
- **纵向研究**：开展持续数周或数月的长期实验，评估系统对日常生活独立性、认知负荷与数字福祉的累积影响
- **包容性设计**：针对低视力、认知障碍、老年用户等可能最受益于情境感知辅助的群体进行专门评估与界面适配
- **高风险场景验证**：在医疗辅助、工业安全等高风险环境中测试系统可靠性，超出当前的游戏辅导与日常提醒场景

---

### 5. 感知与意图理解的精度提升
基于失败分析（第4.3节）识别的具体改进点：
- **鲁棒的第一人称骨干网络**：增强在低光照、快速头部运动等恶劣条件下的视觉感知能力
- **主动确认机制**：在指示性引用（deictic reference）歧义或置信度低时，强制引入显式确认轮次（confirmation turns），而非依赖单次推理
- **多模态融合优化**：改进手势、 gaze 与语音的时序对齐与联合推理，减少模态间的冲突与误解

---

### 6. 算法适应性的理论深化
澄清并扩展 Hierarchical Context Compression（HCC）与 Temporal Chain-of-Thought（T-CoT）的理论基础：
- **在线检索 vs. 离线 RAG**：进一步区分动态流式压缩与传统静态向量数据库检索在时序依赖建模上的本质差异
- **类人记忆机制**：探索更符合人类认知记忆模式（如遗忘曲线、情境依赖回忆）的上下文管理策略，替代当前简单的时序分块与摘要
- **长上下文 MLLM 的协同**：研究如何将 HCC/T-CoT 与具备超长上下文窗口（如 1M+ tokens）的新兴模型有效结合，而非简单替代

---

### 7. 工具生态的扩展与标准化
- **工具发现与自动编排**：当前工具由人工注册至 MCP，未来可探索 LLM 自动发现、组合甚至生成新工具（tool creation）的能力
- **跨设备互操作性**：深化 MCP 协议在不同可穿戴设备（AR 眼镜、助听器、智能手表）间的标准化，实现无缝的能力迁移与任务接力

这些方向共同指向构建**技术上更可靠、伦理上更负责、部署上更可持续**的 Web 原生第一人称智能体系统。

## 总结

该论文提出 **Egocentric Co-Pilot**，一个面向智能眼镜的 Web 原生神经符号框架，旨在解决第一人称（egocentric）AI 助手在复杂现实环境中的部署难题。以下是主要内容概述：

---

### 1. 研究背景与核心挑战
针对智能眼镜等可穿戴设备构建始终在线的 AI 助手面临三重根本性障碍：
- **单模型局限**：端到端多模态大语言模型（MLLMs）在需要精确符号推理的专门任务（如策略棋盘游戏、复杂日程规划）上表现不佳，易产生幻觉或回避性回答。
- **多模态歧义**：物理环境中的指令（如"分析这个"）具有指示性歧义（deictic ambiguity），需融合噪声语音与视觉输入（手势、视线）进行实时消解。
- **长程上下文**：连续第一人称视频流超出模型上下文窗口，传统方法难以维护跨越数小时的长时序依赖与细粒度时间推理。

---

### 2. 方法论：Egocentric Co-Pilot 框架
论文提出由 LLM 编排的模块化架构，包含四个核心组件：

**（1）第一人称推理核心（Egocentric Reasoning Core）**
通过双层次策略处理连续视频流：
- **时序思维链（Temporal Chain-of-Thought, T-CoT）**：针对短期细粒度分析，程序化选择相关时间窗口，构建局部叙事线。
- **分层上下文压缩（Hierarchical Context Compression, HCC）**：针对长程记忆，将历史日志划分为时间块，经文本模型摘要后按查询相关性筛选，与 T-CoT 上下文拼接：
  $$C_{final} = \text{HCC}(E_{historical}, Q) \oplus \text{T-CoT}(E_{recent}, Q)$$

**（2）LLM 编排的神经符号执行（LLM-Orchestrated Neuro-Symbolic Execution）**
采用 **Model-Context Protocol (MCP)** 作为轻量级工具接口，将感知、符号推理与 Web API 封装为可调用的 JSON-Schema 描述函数。执行遵循"发现-规划-执行-合成"循环：
$$R_{final} = \text{LLM.Synthesize}\left(Q, \bigcup_{i} \text{MCP.CallTool}(T_i, Args_i)\right)$$
典型工具如棋盘游戏助手：视觉模块（神经）提取棋盘状态 $\rightarrow$ 确定性引擎（符号）搜索最优着法 $\rightarrow$ LLM 生成战略解释。

**（3）设备端感知与 WebRTC 交互**
针对资源受限硬件设计实时流水线：
- 设备端：并行处理音频（能量基 VAD 与全双工打断检测）与视频（裁剪、下采样）。
- 传输：采用 WebRTC（Opus 音频、H.264 视频、数据通道）实现云端双向低延迟通信，对比 WebSocket 基线展示云卸载与本地推理的权衡。

**（4）主动多模态意图消解（Proactive Multimodal Intent Disambiguation）**
当检测到高不确定性时，系统通过 3D 射线投射（raycasting）将用户手势映射至物理对象，或主动发起澄清查询：
$$\phi^* = \arg\max_{\phi_k \in \Phi \cup \{ask\}} U(\phi_k | x_{1:t}, v_{1:t}, s_t)$$
以零样本方式包装底层模型，无需重新训练即可增强歧义处理能力。

---

### 3. 实验验证
**基准测试**：在 Egolife（长视频 QA）与 HD-EPIC（动作中心 QA）上分别达到 **40.9%** 与 **46.2%** 准确率，超越 GPT-4o、Gemini-1.5-Pro 等基线。消融实验验证 HCC 对长程记忆（+2.0–4.7 点）与 T-CoT 对时间推理的关键贡献。

**真实世界评估**：在智能眼镜上部署端到端系统，三类任务（基础工具使用、具身策略任务、复杂神经符号推理）的任务完成率（TCR）达 **98–98.5%**。

**人机对比研究**：相比 Rabbit r1、Ray-Ban Meta、Apple Vision Pro 等商用设备，Egocentric Co-Pilot 在 5 点李克特量表上获得 **4.70** 分（人类基线 4.90），显著优于最佳竞品（4.61），且在客观任务完成率上表现最优。

---

### 4. 主要贡献
- **神经符号架构**：通过 MCP 协议实现 LLM 与专门模块（感知、符号引擎、Web API）的灵活编排，克服单模型局限。
- **长时序上下文管理**：HCC 与 T-CoT 的结合使系统能处理超越上下文窗口的连续第一人称视频，支持长程问答与决策。
- **Web 原生实时系统**：基于 WebRTC 的云端流水线为资源受限设备提供低延迟多模态交互，同时保持浏览器端可访问性与可审计性。
- **辅助性 AI 设计**：聚焦日常实用任务（阅读标签、日程管理、情境辅导），通过主动澄清与运行时防护（模式验证、用户确认）提升可靠性，优先保障用户自主性与数字福祉而非仅优化参与度。

该工作为构建可部署、负责任且包容的 Web 原生第一人称智能体提供了具体的技术蓝图。
