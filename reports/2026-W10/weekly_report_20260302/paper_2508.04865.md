# Agnostics: Learning to Code in Any Programming Language via Reinforcement with a Universal Learning Environment

## 摘要

> 本文提出了一种名为Agnostics的语言无关后训练管道，旨在解决大语言模型在低资源编程语言上代码生成能力不足的问题。该方法通过将代码评估标准统一为外部可观察行为，使用单一验证器测试任何编程语言的解决方案，显著降低了为每种新语言构建训练基础设施的工程成本。在Lua、Julia、R、OCaml和Fortran五种低资源语言上的实验表明，该方法能有效提升中小规模模型（≤16B参数）的性能，使其达到甚至超越更大规模开源模型的水平。作者团队来自学术界和工业界，其中包含与Qwen、DeepSeek等知名模型相关的机构，体现了产研结合的特点。

## 问题定义

这篇论文试图解决大型语言模型（LLMs）在低资源编程语言中的代码生成能力不足的问题。具体来说，论文指出，尽管LLMs在高资源语言（如Python和JavaScript）中已经能够很好地生成代码，但在低资源语言（如Fortran、Julia等）中表现不佳。这种能力差距主要是由于以下两个原因：

1. **预训练数据的不均衡**：高资源语言有大量的预训练数据，而低资源语言的数据相对较少。例如，The Stack V2（最大的公共代码预训练数据集）中Python代码约有200GB，而Julia和Fortran代码分别只有约2GB和0.07GB。

2. **后训练数据和基础设施的缺乏**：当代LLMs的开发依赖于高质量的监督微调数据和精心设计的强化学习环境，这些都需要大量的人力和专业知识，而低资源语言难以获得这样的资源。

为了解决这些问题，论文提出了一种名为Agnostics的方法，旨在通过一种语言无关的后训练流程来提高LLMs在低资源编程语言中的代码生成能力。该方法的核心思想是通过外部可观察的行为（如输入/输出）来评估代码的正确性，从而使得一个单一的验证器可以测试任何语言的解决方案。

## 相关工作

论文中提到了以下相关研究：

### 数据稀缺性与低资源语言
- **预训练数据的不均衡**：论文指出，现有的预训练数据集（如The Stack V2）中，代码数据主要集中在少数几种编程语言上，而低资源语言的数据量极少。这导致了LLMs在高资源语言上表现良好，但在低资源语言上表现不佳。
- **数据稀缺的应对策略**：论文提到，尽管可以通过在预训练阶段对低资源语言进行上采样或在微调阶段使用预训练数据来提高模型性能，但这些方法的效果有限。

### 低资源语言的合成数据
- **合成数据生成**：一些研究尝试使用LLMs生成合成数据来微调模型，但这些方法在低资源语言上效果不佳，因为生成的数据质量低，且缺乏验证机制。
- **MultiPL-T**：这是一个结合合成数据生成和验证的工作，通过拒绝采样生成符合测试用例的程序。然而，这种方法存在局限性，如对模型生成有效程序的要求高，以及需要为每种低资源语言编写测试用例翻译器。

### 编程任务上的强化学习
- **强化学习的应用**：一些研究将强化学习应用于编程任务，如DeepSeek R1，但这些研究主要针对高资源语言，如Python、Java和C++。
- **强化学习的改进**：论文中提到了一些改进强化学习效率的技术，如Group-Relative Policy Optimization（GRPO）算法，以及如何将其应用于编程任务。

### 其他相关工作
- **代码生成模型**：如SantaCoder、WizardCoder等，这些模型专注于代码生成任务，并在高资源语言上取得了良好的效果。
- **代码优化**：一些研究使用强化学习来优化代码性能，如Afterburner。
- **多语言基准测试**：如MultiPL-E，这是一个用于评估LLMs在多种编程语言上性能的基准测试，但其任务相对简单，对于前沿模型来说不够具有挑战性。

这些相关研究为Agnostics方法提供了背景和基础，同时也展示了Agnostics在解决低资源语言代码生成问题上的创新和优势。

## 解决方案

论文通过提出Agnostics方法来解决LLMs在低资源编程语言中代码生成能力不足的问题。Agnostics的核心思想是通过外部可观察的行为（如输入/输出）来评估代码的正确性，从而使得一个单一的验证器可以测试任何语言的解决方案。这种方法消除了针对每种语言进行单独工程化的需要。具体步骤如下：

### 数据准备阶段
1. **数据集转换**：使用LLM将特定语言的数据集转换为语言无关的格式。例如，将MBPP（Mostly Basic Programming Problems）数据集中的问题描述和测试用例转换为标准输入/输出格式。
2. **语言配置**：为每种目标语言编写一个简短的配置文件，指定如何编译和运行该语言的代码。配置文件还包含一个提示前缀，用于指导模型生成目标语言的代码。

### 训练阶段
1. **强化学习算法**：使用Group-Relative Policy Optimization（GRPO）算法进行强化学习，结合可验证奖励（Verifiable Rewards, VR）来训练模型。GRPO算法通过生成一组候选解决方案，并根据验证器的反馈来更新模型参数。
2. **代码执行环境**：开发了一个语言无关的代码执行沙箱，用于验证模型生成的代码是否符合预期的输入/输出行为。沙箱环境能够处理各种语言的代码，并在执行过程中施加资源限制，以防止模型生成的代码出现异常行为。

### 实现细节
- **训练框架**：使用Ray框架实现训练和代码执行环境，支持多进程和分布式计算。训练过程可以在不同的硬件节点上并行进行，提高训练效率。
- **超参数选择**：通过实验选择了适合的超参数，如学习率、GRPO组大小等。这些超参数的选择基于对不同设置下的训练效果的评估。

### 实验和评估
- **训练数据集**：使用Ag-Codeforces-X作为主要训练数据集，该数据集基于Open-R1 Codeforces竞赛编程问题。
- **基准测试**：使用MultiPL-E和新提出的Ag-LiveCodeBench-X作为评估基准。Ag-LiveCodeBench-X是一个多语言版本的LiveCodeBench，包含499个使用标准输入/输出格式的问题。
- **结果**：Agnostics方法在多个低资源语言（如Lua、Julia、R、OCaml和Fortran）上显著提高了模型性能，达到了新的最佳水平。例如，使用Ag-Codeforces-X训练的Qwen 3 4B模型在Ag-LiveCodeBench-X上的表现接近甚至超过了16B-70B参数的开放权重模型。

### 定性改进
- **错误类型分析**：通过分析模型生成的代码中的错误类型，发现Agnostics训练后的模型在减少基本语言使用错误方面取得了显著进展，如语法错误、内置函数误用等。这表明训练后的模型对目标语言的理解更加深入。

通过上述方法，Agnostics不仅提高了LLMs在低资源语言中的代码生成能力，还减少了针对每种语言进行单独工程化的需要，使得模型能够更广泛地应用于多种编程语言。

## 实验验证

论文中进行了以下几类实验来验证Agnostics方法的有效性：

### 1. **训练数据集的准备和转换**
- **Ag-MBPP-X**：将MBPP数据集转换为语言无关的格式。MBPP包含974个问题，其中776个问题被成功转换为Ag-MBPP-X。
- **Ag-Codeforces-X**：基于Open-R1 Codeforces竞赛编程问题创建的数据集。训练集包含5369个问题，测试集包含107个问题。
- **Ag-LiveCodeBench-X**：从LiveCodeBench数据集中提取499个使用标准输入/输出格式的问题，转换为Agnostics格式。

### 2. **模型训练**
- **模型选择**：使用Qwen 3 4B、Qwen 3 8B、DeepSeek Coder 6.7B Instruct和Phi 4 Mini Instruct等模型进行训练。
- **训练配置**：为每种目标语言编写了简短的配置文件，指定如何编译和运行代码。配置文件还包含一个提示前缀，用于指导模型生成目标语言的代码。
- **训练过程**：使用Group-Relative Policy Optimization（GRPO）算法进行强化学习，结合可验证奖励（Verifiable Rewards, VR）来训练模型。训练过程中，模型生成的代码在语言无关的代码执行沙箱中进行验证。

### 3. **基准测试**
- **MultiPL-E**：一个广泛使用的多语言编程基准测试，包含从Python转换而来的测试用例。用于评估模型在多种编程语言上的性能。
- **Ag-LiveCodeBench-X**：新提出的多语言版本的LiveCodeBench，包含499个使用标准输入/输出格式的问题。用于评估模型在更复杂任务上的性能。

### 4. **性能评估**
- **Qwen 3 4B模型**：
  - 在Ag-LiveCodeBench-X上，Qwen 3 4B模型在Lua、Julia、R、OCaml和Fortran上的性能显著提高，分别达到了23%、22%、15%、7%和15%的pass@1准确率。
  - 在MultiPL-E上，Qwen 3 4B模型在Lua、Julia和R上的性能也有所提高，分别达到了64%、54%和43%的pass@1准确率。
- **Qwen 3 8B模型**：
  - 在Ag-LiveCodeBench-X上，Qwen 3 8B模型在Lua、Julia和R上的性能分别为25%、25%和19%。
  - 在MultiPL-E上，Qwen 3 8B模型在Lua、Julia和R上的性能分别为68%、61%和52%。
- **其他模型**：
  - DeepSeek Coder 6.7B Instruct和Phi 4 Mini Instruct模型在Lua、Julia和R上的性能也有所提高，但Phi 4 Mini Instruct在R上的性能没有显著提升。

### 5. **错误类型分析**
- **错误分类**：使用LLM对模型生成的代码中的错误进行分类，分析了以下几类错误：
  - 语法和拼写错误
  - 输入读取和解析错误
  - 未初始化变量
  - 数据类型和转换错误
  - 函数误用和缺少库
  - 算法逻辑错误
  - 输出格式和呈现错误
- **结果分析**：训练后的模型在减少基本语言使用错误方面取得了显著进展，如语法错误、内置函数误用等。这表明训练后的模型对目标语言的理解更加深入。

### 6. **训练动态分析**
- **训练曲线**：记录了训练过程中GRPO组批处理的pass@1准确率和测试集的pass@1准确率。结果显示，训练集和测试集的准确率在训练过程中保持高度相关，表明模型在训练过程中持续改进。

### 7. **硬件和软件环境**
- **硬件**：使用了三台机器进行训练和评估，包括B、R1和R2。这些机器配备了不同的CPU、GPU和内存配置。
- **软件**：使用了Ray、Torch、Transformers等Python库来实现训练框架。

通过这些实验，论文验证了Agnostics方法在提高LLMs在低资源编程语言中的代码生成能力方面的有效性，并展示了该方法在不同模型和数据集上的广泛适用性。

## 总结

论文《Agnostics: Learning to Code in Any Programming Language via Reinforcement with a Universal Learning Environment》介绍了一种名为Agnostics的方法，旨在通过强化学习提高大型语言模型（LLMs）在低资源编程语言中的代码生成能力。该方法通过将代码的正确性评估基于其外部可观察行为（如输入/输出），使得一个单一的验证器可以测试任何语言的解决方案，从而消除了针对每种语言进行单独工程化的需要。

### 背景知识
- **LLMs在编程任务中的表现**：LLMs在高资源语言（如Python和JavaScript）中表现出色，但在低资源语言（如Fortran、Julia等）中表现不佳。这种差距主要是由于预训练数据的不均衡和后训练数据及技术的缺乏。
- **数据稀缺性**：低资源语言的预训练数据量少，且缺乏高质量的后训练数据集和强化学习环境。
- **现有方法的局限性**：现有的方法如MultiPL-T虽然能够生成合成数据并进行验证，但依赖于复杂的测试用例翻译器，且对模型生成有效程序的要求高。

### 研究方法
Agnostics方法的核心思想是通过外部可观察行为来评估代码的正确性，从而实现语言无关的强化学习环境。具体步骤如下：

1. **数据集转换**：使用LLM将特定语言的数据集转换为语言无关的格式。例如，将MBPP数据集中的问题描述和测试用例转换为标准输入/输出格式。

3. **强化学习**：使用Group-Relative Policy Optimization（GRPO）算法进行强化学习，结合可验证奖励（Verifiable Rewards, VR）来训练模型。模型生成的代码在语言无关的代码执行沙箱中进行验证。
